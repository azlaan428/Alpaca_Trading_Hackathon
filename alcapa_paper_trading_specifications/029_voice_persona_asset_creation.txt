1.1. Abstract
This document defines how synthetic caller voice assets for VoiceGate's persona archetypes
(voice_processing_specifications/027_persona_archetype_definitions.txt) are created, named,
validated, and integrated into the repository. It operationalizes each archetype's behavioral
identity into production-ready TTS (text-to-speech) voice asset standards for the persona
engine (`src/voicegate/persona_engine`).

1.2. Key Words
TTS, text-to-speech, synthetic voice, persona voice consistency, export format, attribution,
license compliance, QA checklist, VoiceGate.

1.3. Executive Summary
Synthetic caller voice assets must be behaviorally consistent with the persona archetype they
represent and technically consistent with the transcription/telephony ingestion requirements
of the call orchestrator (`src/voicegate/call_orchestrator`). This file defines voice-asset
categories, required formats, naming/versioning conventions, source-attribution obligations
for TTS models/voices, and a QA gate checklist that blocks non-compliant voice assets from
integration.

1.4. Key Findings
1.4.1. Voice-per-archetype consistency is mandatory: the same persona archetype must use the
same TTS voice (or voice family) across every call in a gauntlet run, so variance-injection
effects (voice_processing_specifications/026_randomization_variance_terminology.txt) are
attributable to scripted behavior, not accidental voice-identity drift.
1.4.2. Technical consistency (sample rate, channel layout, encoding) is mandatory for
transcription-engine reliability and dual-channel call recording.
1.4.3. Every TTS voice asset requires provenance metadata (voice/model identity, license) and
license-compatibility verification before use in a scored gauntlet run.
1.4.4. The asset QA checklist is a release gate, not an optional review note.

1.5. Philosophical Preamble
In a compliance test bench, a caller's voice is part of the test's realism, not decoration.
An inconsistent or unlicensed voice asset undermines the credibility of every verdict
produced using it.

1.6. Scope and Authority
1.6.1. This file governs creation and acceptance of synthetic caller voice assets.
1.6.2. Code-level integration details are governed by
voice_processing_specifications/006_voicegate_scaffolding.txt and
voice_processing_specifications/023_voicegate_modules_imports.txt.
1.6.3. If a behavioral/voice conflict occurs,
voice_processing_specifications/027_persona_archetype_definitions.txt is the behavioral
source of truth.

1.7. Asset Taxonomy
1.7.1. Persona voice profiles: one TTS voice (or bounded voice family) per canonical persona
archetype (voice_processing_specifications/027_persona_archetype_definitions.txt §1.7).
1.7.2. Prosody presets: tone, pace, and pause settings mapped to a persona's Patience and
Escalation Rate stats.
1.7.3. Scenario-specific voice cues: short recorded/synthesized markers for scripted
escalation beats (e.g. a raised-voice segment at High/Extreme intensity tiers).
1.7.4. Reference/QA audio: short sample clips used for peer review and regression checks.

1.8. Voice Selection and Consistency Constraints
1.8.1. Each persona archetype is assigned exactly one primary TTS voice identity; a
secondary/backup voice may be documented but is not mixed mid-run without recording the
substitution in the run's event log.
1.8.2. Voice pitch/pace variation driven by tone jitter
(voice_processing_specifications/026_randomization_variance_terminology.txt §1.8.1) must stay
within a documented bounded range so the same underlying voice remains recognizable across a
run.
1.8.3. Voice selection must not encode or imply real-world protected-characteristic
stereotypes; persona behavioral traits (Section
voice_processing_specifications/027_persona_archetype_definitions.txt §1.9) drive behavior,
not the voice's demographic signal.

1.9. File Formats and Technical Constraints
1.9.1. Source/master audio: WAV, 16-bit or higher, mono, minimum 16 kHz sample rate (telephony-
compatible), higher sample rates permitted for archival masters.
1.9.2. Runtime delivery: OGG or MP3 permitted where the call orchestrator's TTS/telephony
pipeline requires compressed delivery; WAV preferred where bandwidth is not a constraint.
1.9.3. Every voice-asset pack must include a manifest with persona id, voice identity/model,
sample rate, and license reference.

1.10. Naming and Versioning Rules
1.10.1. Naming convention: `voice_<persona_archetype>_<descriptor>_v<major>_<minor>.<ext>`.
1.10.2. Examples:
1.10.2.1. `voice_distressed_caller_primary_v1_0.wav`.
1.10.2.2. `voice_adversarial_negotiator_escalation_cue_v1_1.wav`.
1.10.3. Breaking voice-identity changes (switching TTS model/voice) increment major version;
prosody-preset refinements increment minor version.

1.11. Source Attribution and Licensing Controls
1.11.1. Every TTS-model-derived voice asset must record the model/tool identity, voice name,
and license terms in the manifest.
1.11.2. Voice assets with incompatible commercial-use or redistribution terms are prohibited
from use in scored gauntlet runs.
1.11.3. AI-generated voice assets must record prompt/configuration, model/tool identity, and
generation date.
1.11.4. Cloned or likeness-based voices of real, identifiable individuals are prohibited
unless formally licensed with explicit, documented consent.

1.12. Asset QA and Acceptance Checklist
1.12.1. Behavioral conformance checks:
1.12.1.1. Voice-per-persona consistency (Section 1.8.1).
1.12.1.2. Prosody preset alignment with the persona's Patience/Escalation Rate stats.
1.12.2. Technical checks:
1.12.2.1. Correct file format and sample rate.
1.12.2.2. No corrupt or clipped audio.
1.12.2.3. Manifest completeness.
1.12.3. Governance checks:
1.12.3.1. Provenance metadata present.
1.12.3.2. License compatibility verified.
1.12.3.3. Naming/versioning compliant.

1.13. Integration Workflow with Engineering
1.13.1. Voice-asset branch preparation and review.
1.13.2. QA checklist execution and sign-off.
1.13.3. Manifest and references added to `src/data/personas`.
1.13.4. Integration test pass for voice loading, fallback behavior, and transcription-engine
compatibility.
