1.1. Abstract
This document defines randomization and variance-injection terminology for all seeded-random
persona behavior in VoiceGate. It standardizes notation, injection interpretation, and
logging vocabulary so that design, implementation, and testing teams use one shared language
for probabilistic caller behavior, based on the same "deterministic seeded randomness"
role such mechanisms played in the sibling project's dice system
(voice_processing_specifications/0000_documentation_standards.txt records this repurposing
lineage).

1.2. Key Words
tone jitter, interruption timing, escalation rate, seeded RNG, rng_service, contested
variance, deterministic ordering, audit log, probability baseline, VoiceGate.

1.3. Executive Summary
VoiceGate uses seeded pseudo-random variance injection — tone jitter, interruption timing,
and escalation rate — to make each simulated caller in a gauntlet run behave with bounded,
reproducible unpredictability rather than fixed scripted delivery. This file defines the
canonical terms and equations that map a persona's base behavioral stats
(voice_processing_specifications/027_persona_archetype_definitions.txt §1.9) plus a sampled
variance roll to an actual in-call behavior, based on the scenario intensity-tier contract
in voice_processing_specifications/025_scenario_persona_catalog.txt §1.9. It also defines
required logging fields so each run can be replayed and verified.

1.4. Key Findings
1.4.1. The system uses `rng_service` (`src/voicegate/rng_service`) as the single seeded RNG
source in MVP scope; no unseeded/non-reproducible randomness is used in scored runs.
1.4.2. In-call behavior is determined by combining a persona's base stat with a sampled
variance roll, not by raw sampled values alone.
1.4.3. Variance semantics must be logged as structured events to preserve auditability and
enable exact run replay from a recorded seed.
1.4.4. Terminology drift (e.g., "jitter" vs "wobble") is a reconciliation risk and is banned.

1.5. Philosophical Preamble
Chance is allowed in a compliance test bench only when it can be explained after the fact. A
sampled variance value is not a black box event; it is a state transition with evidence, and
that evidence is what lets a Risk Report's Fail verdict be reproduced and defended.

1.6. Scope and Authority
1.6.1. This file governs terms and meaning, not persona-stat tuning.
1.6.2. Persona-stat changes that alter equations belong in
voice_processing_specifications/027_persona_archetype_definitions.txt first, then here.

1.7. Randomization Notation Standard
1.7.1. `seed` means the integer value used to initialize `rng_service` for one gauntlet run;
the same `seed` reproduces the same sequence of variance rolls.
1.7.2. `roll` refers to one sampled variance value in the normalized range [0.0, 1.0].
1.7.3. "Value" refers to a persona base stat plus its applicable variance roll contribution.
1.7.4. "Resample" means discarding a prior sampled value and drawing one new sample from the
same seeded stream, where explicitly allowed by a scenario's escalation script.

1.8. Variance Injection Contract
1.8.1. tone_jitter_value = persona.tone_baseline + (roll - 0.5) * persona.tone_variance_band.
1.8.2. interruption_timing_value = persona.patience_stat - roll * scenario.pressure_factor.
1.8.3. escalation_rate_value = persona.escalation_rate_stat + roll *
scenario.intensity_multiplier (voice_processing_specifications/025_scenario_persona_catalog.txt
§1.9 intensity-tier magnitude).
1.8.4. If escalation_rate_value crosses the scenario's scripted escalation-point threshold,
the persona advances to its next scripted escalation beat.
1.8.5. A call reaching its final scripted escalation beat without agent resolution triggers a
scenario-defined terminal state (e.g. "caller disconnects," "caller demands supervisor").

1.9. Outcome Terminology
1.9.1. High Volatility: sampled roll drives value more than 0.75 of the variance band from
baseline (analytics label only).
1.9.2. Standard Variance: sampled roll drives value within 0.25-0.75 of the variance band.
1.9.3. Baseline Hold: sampled roll drives value within 0.25 of baseline.
1.9.4. Labels in 1.9 are reporting vocabulary and do not alter escalation rules.

1.10. Probability Baseline
1.10.1. For `rng_service`, P(roll in any sub-interval of equal width within [0.0, 1.0]) is
uniform by construction (uniform distribution requirement).
1.10.2. With a persona's default variance band and no scenario modifiers, the probability of
a Baseline Hold outcome (Section 1.9.3) is 0.5.
1.10.3. Extreme-tier scenarios (voice_processing_specifications/025_scenario_persona_catalog.txt
§1.9) widen the effective variance band, shifting probability mass toward High Volatility.

1.11. Logging and Audit Terminology
1.11.1. Required fields per variance-injection event:
1.11.1.1. event_id.
1.11.1.2. call_id.
1.11.1.3. persona_id and scenario_id.
1.11.1.4. seed and roll_index (position of this roll within the seeded stream).
1.11.1.5. base_stat_name and base_stat_value.
1.11.1.6. sampled_roll.
1.11.1.7. resulting_value.
1.11.1.8. outcome_label from Section 1.9.
1.11.2. Field names should align with
voice_processing_specifications/021_voicegate_data_standards.txt naming guidance.

1.16. Conclusion
This file provides a single vocabulary and equation contract for all seeded-variance-driven
persona behavior, reducing ambiguity across implementation, QA, and Risk Report analytics,
and preserving reproducibility of any run given its recorded seed.
