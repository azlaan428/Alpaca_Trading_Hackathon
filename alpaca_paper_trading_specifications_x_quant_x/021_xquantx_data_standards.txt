1.1. Abstract
This document specifies which of the pre-approved data formats — CSV, JSON, HTML, XML,
ARXML, XSLX, PICKLE, DB — apply to which VoiceGate data concern, elaborating the original
format-list baseline directive into concrete per-use-case selection rules for transcripts,
verdict records, and statutory/company-terms snapshots.

1.2. Key Words
data format, CSV, JSON, HTML, XML, ARXML, XLSX, pickle, database, transcript schema, verdict
record, export, security, VoiceGate.

1.3. Executive Summary
VoiceGate uses JSON as its primary schema for transcripts, verdict records, and persona/
scenario definitions (`src/data/personas`, `src/data/scenarios`,
`src/data/statutory_rules`, `src/data/company_terms_snapshots`), CSV/XSLX for tabular Risk
Report and run-statistics export, and reserves HTML/XML/ARXML/DB for optional downstream
reporting. PICKLE is explicitly restricted per the security guidance in Section 1.10,
consistent with OWASP guidance against deserializing untrusted pickled data.

1.4. Key Findings
1.4.1. All eight formats named in the original baseline directive (Section 1.6) remain
approved formats for this project; this document assigns each to concrete VoiceGate use
cases rather than removing any.
1.4.2. JSON is the primary format for transcript records and verdict records (Section 1.8),
for human-readability, diffability, and broad tooling support during audit/review.
1.4.3. CSV and XSLX (XLSX) are reserved for tabular Risk Report and run-statistics export,
useful for cross-run calibration review (per the judge-calibration-chart deliverable).
1.4.4. PICKLE is restricted to trusted, locally-generated, same-version data only (e.g.
ephemeral development-only caches), and must never be used to deserialize transcript,
statute, or company-terms data from an untrusted or external source, per OWASP guidance on
insecure deserialization.
1.4.5. HTML, XML, ARXML, and DB formats are reserved for future/optional reporting,
interchange, or persistence needs not required by the MVP, and are not currently wired into
any required MVP data path.

1.5. Philosophical Preamble
A data format is a security boundary as much as a serialization choice. This document keeps
faith with the original baseline's full format list while making explicit which formats are
safe defaults for compliance-sensitive data (transcripts, statute citations, company terms)
and which (PICKLE, in particular) require a narrower, trust-bounded use case, in keeping
with this project's OWASP Top 10 security discipline.

1.7. Format Selection Criteria and Use Cases
| Format | Primary Use Case in VoiceGate |
|--------|-------------------------------------|
| JSON | Transcript records, verdict records, persona/scenario definitions, event-log export |
| CSV | Tabular Risk Report / run-statistics export for spreadsheet analysis |
| XSLX (XLSX) | Tabular Risk Report export where formatting/multi-sheet support is desired |
| HTML | Optional human-readable Risk Report rendering (reserved, not MVP-required) |
| XML | Optional structured interchange with external compliance tooling (reserved) |
| ARXML | Reserved for potential future structured interchange (no current use case) |
| PICKLE | Trusted, same-version, locally generated ephemeral caches only; never for untrusted/external data (Section 1.10) |
| DB | Reserved for a potential future embedded persistence layer (reserved, not MVP-required) |

1.8. Transcript and Verdict Record Schemas
1.8.1. A transcript record is serialized as JSON with, at minimum: `call_id`, dual-channel
turns (`speaker: agent|caller`, `text`, `timestamp`), `persona_id`, and `scenario_id`.
1.8.2. A verdict record is serialized as JSON with, at minimum: `call_id`, `verdict:
PASS|FAIL|FLAG`, `rule_id` (voice_processing_specifications/028_statutory_ruleset_integration.txt
citation format), `clause_or_section`, and `rationale`.
1.8.3. Both schemas are chosen for human-readability, diffability, and freedom from the
arbitrary-code-execution risk associated with PICKLE deserialization, consistent with OWASP
secure-deserialization guidance, since transcripts may originate from an untrusted call.

1.9. Statistics and Risk Report Export Formats
Run statistics (voice_processing_specifications/010_voicegate_run_statistics.txt) and Risk
Report line items may be exported as JSON (default, structured), CSV, or XSLX (for
spreadsheet analysis, e.g. reviewing judge-model calibration across runs).

1.10. Data Format Prohibitions
1.10.1. PICKLE must never be used to load data from an untrusted or externally supplied
source (e.g. a transcript or company-terms snapshot fetched at runtime), since Python's
`pickle` module can execute arbitrary code during deserialization; this is a binding
OWASP-aligned security rule, not merely a style preference.
1.10.2. Transcript records, verdict records, and any data crossing a trust boundary (call
audio/text, scraped company terms) must use JSON, never PICKLE.

PICKLE explicitly bounded to prevent insecure deserialization of untrusted data.
