1.1. Abstract
This document specifies which data formats apply to which X Quant X data concern, and
provides the canonical JSON schema definitions for all primary data types: OHLCVBar, Tick,
Order, Position, PortfolioSnapshot, RegimeState, Signal, and PerformanceMetrics. It
elaborates the original format-list baseline (preserved verbatim in Section 1.6) into
concrete per-use-case selection rules for all data paths in the platform.

1.2. Key Words
data format, JSON schema, CSV, Parquet, Arrow, TOML, SQLite, OHLCV, tick, order, position,
portfolio, regime state, signal, timestamp precision, UTC nanoseconds, null handling,
forward-fill policy, schema versioning.

1.3. Executive Summary
X Quant X uses JSON as the primary schema for all event-driven data (orders, fills, regime
transitions, signals, audit log entries). Parquet/Arrow is used for bulk historical
time-series data (OHLCV bars, ticks) in the Rust data pipeline. CSV is used for export and
cross-run analysis (performance metrics, attribution). TOML is used for all configuration
(config/). SQLite or TimescaleDB is used for persistent session storage (trade history, fill
history). All timestamps are UTC nanoseconds since epoch (int64). All prices are IEEE 754
double precision. PICKLE is restricted to trusted, same-version, local ephemeral caches
only.

1.4. Key Findings
1.4.1. All eight formats named in the original baseline directive (Section 1.6) remain
approved for this project; this document assigns each to concrete X Quant X use cases.
1.4.2. JSON is the primary format for event-driven data and audit log entries (Section 1.8),
for human-readability and diffability during audit.
1.4.3. Parquet/Arrow (via pyarrow, arrow2) is the primary format for bulk OHLCV and tick
data stored and processed by the Rust pipeline and consumed by Python ML/research.
1.4.4. All timestamps are int64 UTC nanoseconds since epoch. No local time. No ambiguous
timezone strings. Conversion to display-friendly format is done only in the dashboard layer.
1.4.5. PICKLE is restricted per OWASP insecure deserialization guidance: trusted, locally
generated, same-version ephemeral caches only. Never for OHLCV data, order data, or any
data from an external source.
1.4.6. Forward-fill policy for missing bars: gaps of <= 5 consecutive bars are
forward-filled with the last known close price (open=high=low=close=prev_close, volume=0,
trade_count=0). Gaps > 5 bars trigger a DataOperator warning and optional replay halt.
1.4.7. Schema versioning: every JSON schema has a `schema_version` field (semver string).
Operators validate `schema_version` before processing. Version mismatches are hard errors
logged to the audit trail.

1.5. Philosophical Preamble
A data format is a security boundary as much as a serialization choice. A system that
naively deserializes untrusted PICKLE data from an external market data source has violated
OWASP insecure deserialization before writing a single line of trading logic. This document
keeps faith with the original baseline's full format list while making explicit which
formats are safe defaults for time-series financial data and which require a narrower,
trust-bounded use case.

| Format           | Primary Use Case in X Quant X                                                              |
|------------------|--------------------------------------------------------------------------------------------|

| TimescaleDB)     |                                                                                            |
| TOML             | Configuration: risk thresholds, regime priors, paper-trading settings (config/)           |

1.8. Canonical Schema Definitions

1.8.1. OHLCVBar (JSON):
{
  "schema_version": "1.0.0",
  "symbol": "AAPL",
  "timestamp": 1700000000000000000,
  "open": 150.25,
  "high": 151.10,
  "low": 149.80,
  "close": 150.90,
  "volume": 1234567.0,
  "vwap": 150.60,
  "trade_count": 8432,
  "timeframe": "1m"
}
Field invariants: high >= open, high >= close, high >= low; low <= open, low <= close;
all prices > 0; volume >= 0.

1.8.2. Tick (JSON):
{
  "schema_version": "1.0.0",
  "symbol": "AAPL",
  "timestamp": 1700000000123456789,
  "price": 150.55,
  "size": 100.0,
  "exchange": "NYSE",
  "conditions": ["R", "F"]
}

1.8.3. Order (JSON -- submitted state):
{
  "schema_version": "1.0.0",
  "order_id": "uuid-v4",
  "client_order_id": "xqx-20261231-001",
  "symbol": "AAPL",
  "side": "buy",
  "type": "market",
  "qty": 10.0,
  "filled_qty": 0.0,
  "limit_price": null,
  "stop_price": null,
  "status": "new",
  "submitted_at": 1700000000000000000,
  "filled_at": null
}
Status transitions are append-only: "new" -> "partially_filled" -> "filled" or "cancelled"
or "expired".

1.8.4. Position (JSON):
{
  "schema_version": "1.0.0",
  "symbol": "AAPL",
  "qty": 10.0,
  "avg_entry_price": 150.25,
  "current_price": 151.00,
  "unrealized_pl": 7.50,
  "unrealized_plpc": 0.005,
  "side": "long"
}

1.8.5. PortfolioSnapshot (JSON):
{
  "schema_version": "1.0.0",
  "timestamp": 1700000000000000000,
  "equity": 105000.0,
  "cash": 55000.0,
  "buying_power": 55000.0,
  "positions": [ ... ],
  "daily_pl": 500.0,
  "total_pl": 5000.0
}

1.8.6. RegimeState (JSON):
{
  "schema_version": "1.0.0",
  "timestamp": 1700000000000000000,
  "regime_id": "R01",
  "regime_probabilities": {
    "R01": 0.62, "R02": 0.15, "R03": 0.10, "R04": 0.03,
    "R05": 0.02, "R06": 0.01, "R07": 0.02, "R08": 0.01,
    "R09": 0.01, "R10": 0.01, "R11": 0.01, "R12": 0.01
  },
  "confidence": 0.74,
  "kalman_state_vector": [0.62, -0.12, 0.08],
  "kalman_covariance_matrix": [[0.04, 0.01, 0.00], [0.01, 0.09, 0.02], [0.00, 0.02, 0.06]]
}
Invariant: regime_probabilities values must sum to 1.0 +/- 1e-9.

1.8.7. Signal (JSON):
{
  "schema_version": "1.0.0",
  "operator_id": "MomentumSignalOperator-v1.0.0",
  "symbol": "AAPL",
  "timestamp": 1700000000000000000,
  "score": 0.72,
  "confidence": 0.85,
  "regime_id": "R01",
  "version": "1.0.0"
}
Invariants: score in [-1, 1]; confidence in (0, 1].

1.9. Statistics and Performance Report Export Formats
1.9.1. Per-session performance metrics are exported as CSV with columns: session_id, date,
total_pl, daily_return, sharpe, sortino, calmar, max_drawdown, regime_attribution (JSON
string), signal_attribution (JSON string).
1.9.2. Audit log entries are exported as newline-delimited JSON (NDJSON) for streaming
compatibility.
1.9.3. A PortfolioSnapshot is emitted at every bar and stored in DB (SQLite) for dashboard
queries.

1.10. Data Format Prohibitions
1.10.1. PICKLE must never be used to serialize or deserialize data from any external source
(Alpaca API, market data feeds, news sources), per OWASP insecure deserialization guidance.
1.10.2. API keys and secrets must never appear in any data file, schema file, or
configuration file committed to version control; load from environment variables only.
1.10.3. Timestamps in local time or without explicit timezone are a hard error; UTC
nanoseconds (int64) is the only accepted format.
1.10.4. Floating-point equality comparisons on price or weight values are prohibited; use
tolerance-based comparison (|a - b| < epsilon) only.

1.11. Summary Table
| Data Type          | Primary Format     | Storage     | Key Invariant                              |
|--------------------|-------------------|-------------|---------------------------------------------|
| OHLCVBar           | JSON / Parquet     | File + DB   | high >= close >= low; all prices > 0        |
| Tick               | JSON / Parquet     | File        | price > 0; size >= 0                        |
| Order              | JSON               | DB          | Status transitions are monotonic            |
| Position           | JSON               | DB          | Updated atomically per fill                 |
| PortfolioSnapshot  | JSON               | DB          | Queried by dashboard per bar                |
| RegimeState        | JSON               | DB          | probabilities sum to 1.0 +/- 1e-9          |
| Signal             | JSON               | DB / Audit  | score in [-1,1]; confidence in (0,1]        |
| Performance metrics| CSV                | File        | Exported per session                        |
| Audit log          | NDJSON             | File + DB   | Hash chain for tamper detection             |
| Config             | TOML               | File        | Declarative only; no executable logic       |

| Risk                                               | Likelihood | Impact   | Mitigation                                                                              |
|----------------------------------------------------|------------|----------|-----------------------------------------------------------------------------------------|

| API keys committed in data files                   | Low        | Critical | Section 1.10.2 prohibition; CI pre-commit secret scanner                                |
