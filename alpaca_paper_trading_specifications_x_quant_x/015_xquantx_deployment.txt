1.1. Abstract
This document defines the local deployment procedure for X Quant X, covering environment
setup, secrets management, Docker containerization option, health-check endpoints, and the
session startup sequence for Paper and Backtest modes.

1.2. Key Words
deployment, local deployment, Docker, environment variables, secrets management, health check,
session startup, Paper mode, Backtest mode, alpaca-py, config.

1.3. Executive Summary
X Quant X is deployed locally for the MVP sprint. Deployment consists of: (1) cloning the
repository and initializing submodules; (2) setting up per-language build environments (per
007_xquantx_virtual_env.txt); (3) configuring secrets via environment variables; (4) starting
the session via a single entry-point command. An optional Docker compose configuration
containerizes all four language services. Health-check endpoints are provided for the Go
streaming service.

1.6. Local Deployment Steps

1.6.1. Clone and Initialize
```bash
git clone <repo_url> Alpaca_Trading_Hackathon
cd Alpaca_Trading_Hackathon
git submodule update --init --recursive
```

1.6.2. Python Environment
```bash
python -m venv .venv-xquantx
source .venv-xquantx/bin/activate  # Windows: .venv-xquantx\Scripts\activate
pip install -r requirements.txt -r requirements-dev.txt
```

1.6.3. Go Service Build
```bash
cd src/go
go mod download
go build -o bin/streamer ./cmd/streamer/
go build -o bin/server ./cmd/server/
```

1.6.4. C++ Kernel Build
```bash
cd src/cpp
conan install . --build=missing -s build_type=Release
cmake -B build -S . -DCMAKE_BUILD_TYPE=Release
cmake --build build --parallel
```

1.6.5. Rust Pipeline Build
```bash
cd src/rust
cargo build --release
```

1.7. Environment Variable Configuration

1.7.1. Required Environment Variables
Set in .env -- must not be committed to VCS:
```
ALPACA_API_KEY=<your_paper_api_key>
ALPACA_SECRET_KEY=<your_paper_api_secret>
ALPACA_BASE_URL=https://paper-api.alpaca.markets
ALPACA_DATA_URL=https://data.alpaca.markets
MONTE_CARLO_SEED=42
SESSION_SEED=42
```

1.7.2. .env.example
A .env.example file is committed to VCS documenting all required variables without values.

1.7.3. Loading via python-dotenv
The Python entry point loads .env via python-dotenv:
```python
from dotenv import load_dotenv
load_dotenv()
```

1.7.4. No Hardcoding Rule
No environment variable may be hardcoded in any source file, per
005_xquantx_coding_standards.txt §1.9.1.

1.8. Session Startup Sequence
Paper mode:
```bash
python -m xquantx.main --mode paper --config config/paper_trading.toml
```

Backtest mode:
```bash
python -m xquantx.main --mode backtest --config config/backtest.toml --data-dir data/historical/
```

Dry-run mode:
```bash
python -m xquantx.main --mode dry_run --config config/paper_trading.toml
```

The entry point: validates config, loads SessionContext, starts the Go streaming service as
a subprocess, initializes the Operator DAG, starts the Dash dashboard on
http://localhost:8050, begins the session loop.

1.9. Docker Deployment (Optional)

1.9.1. docker-compose.yml Services
docker-compose.yml defines four services: xquantx-python, xquantx-go-streamer,
xquantx-go-server, and xquantx-dashboard.

1.9.2. Python Service
Builds from Dockerfile.python using Python 3.14-slim base.

1.9.3. Go Service
Builds from Dockerfile.go using golang:alpine base.

1.9.4. Environment Variable Injection
Environment variables are injected from .env file via `env_file: .env` in
docker-compose.yml.

1.9.5. Dashboard Port
Dashboard exposed on host port 8050.

1.9.6. C++ and Rust Components
C++ and Rust components are compiled into the Python service container as shared libraries
(pybind11/ctypes binding).

1.10. Health-Check Endpoints

1.10.1. Go Streaming Service
GET http://localhost:8080/health returns {"status": "ok", "last_bar_ts": <unix_ns>} when
the WebSocket is connected and delivering bars.

1.10.2. Python Main Process
The Dash dashboard's root page (http://localhost:8050/) returns HTTP 200 when the session
is active.

1.10.3. Startup Probe
On session start, the Python entry point calls GET http://localhost:8080/health and waits
up to 30 seconds for a {"status": "ok"} response before beginning the pipeline loop.

1.11. Secrets Rotation

1.11.1. Alpaca Key Rotation
Alpaca API keys are rotated via the Alpaca dashboard (alpaca.markets). After rotation,
update .env and restart the session.

1.11.2. .env VCS Exclusion
Never commit .env to VCS. The .gitignore already excludes .env.

1.11.3. CI Repository Secrets
CI uses repository secrets (GitHub Actions Secrets) for any sandbox integration test that
requires ALPACA_API_KEY.
