1.1. Abstract
This document defines the UI navigation specification for the X Quant X paper-trading
dashboard. It covers the screen inventory, navigation flow, keyboard navigation requirements,
and screen-specific display rules for the six dashboard panels: Portfolio Overview, Regime
Monitor, Signal Dashboard, Position Detail, Order History, and Risk Audit.

1.2. Key Words
UI navigation, dashboard, portfolio overview, regime monitor, signal dashboard, position
detail, order history, risk audit, Dash, Plotly, keyboard navigation, screen layout.

1.3. Executive Summary
The X Quant X dashboard is a Plotly Dash web application with six top-level panels accessible
via a sidebar navigation. The primary view on session start is the Portfolio Overview panel.
Navigation is sidebar-based with keyboard shortcuts. All panels auto-refresh at the per-bar
interval (default 1 minute in Paper mode). No panel contains a "live trade" button — the
dashboard is monitoring-only; execution is handled by the operator pipeline.

1.4. Key Findings
1.4.1. Six panels cover all monitoring needs: Portfolio Overview (equity + drawdown +
positions), Regime Monitor (regime probabilities + HMM state), Signal Dashboard (per-operator
signal scores + aggregate), Position Detail (per-symbol drill-down), Order History (all
submitted/filled/cancelled orders), Risk Audit (risk-gate verdict log).
1.4.2. The dashboard is monitoring-only: no buttons that submit orders, modify positions, or
override risk rules. All actions are observation, not execution.
1.4.3. Every action that would trigger a configuration change (e.g. switching operating mode
from Paper to Backtest) requires a two-step confirm in a modal dialog, never a single click.
1.4.4. The Regime Monitor panel uses the #FFACE9 alert-critical color (from
002_xquantx_aesthetics.txt) exclusively for R04 and R07 regime highlight states.
1.4.5. Session context (session_id, mode, RULESET_VERSION) is displayed in the dashboard
header at all times.

1.5. Philosophical Preamble
A dashboard that allows observation without accidental execution is the trader's first line
of epistemic discipline. In X Quant X, the dashboard exists to make measured evidence
visible before any consequential action is taken — consistent with the legibility-first and
guardrails-protect-trust design pillars (003_xquantx_philosophy.txt). The monitoring-only
constraint is not a limitation; it is a guarantee: the operator can trust that any state
change in the live system originated from the operator pipeline, not an accidental dashboard
click. This principle is non-negotiable and applies to every panel in §1.6.

1.7. Navigation Structure
1.7.1. Sidebar navigation: left sidebar with 6 panel icons + panel labels. Active panel is
highlighted with text-accent (#7ec8e3) background.
1.7.2. Default panel on session start: P01 Portfolio Overview.
1.7.3. Panel switching: single click on sidebar icon or keyboard shortcut (1–6 for P01–P06).
1.7.4. Keyboard shortcuts: 1=Portfolio Overview, 2=Regime Monitor, 3=Signal Dashboard,
4=Position Detail, 5=Order History, 6=Risk Audit, R=force refresh, Esc=close modal.

1.8. Panel-Specific Display Rules

1.8.1. P01 Portfolio Overview
- Header: current equity ($), daily P&L ($, %), total P&L ($, %), mode (PAPER/BACKTEST) badge
- Equity curve (last 252 bars or session start, whichever is shorter)
- Drawdown waterfall (synchronized time axis with equity curve)
- Portfolio treemap (current positions, sized by weight, colored long=green/short=red)
- Alert: if drawdown > 15%, header background changes to alert-critical (#FFACE9)

1.8.2. P02 Regime Monitor
- Stacked horizontal bar chart: regime probabilities for current bar (R01–R12)
- R04 and R07 segments highlighted with alert-critical color
- Entropy gauge: circular gauge, 0–1 scale, turns alert-critical when U_t > 0.75
- Regime history: last 60 bars shown as a color-coded timeline (most-probable regime per bar)

1.8.3. P03 Signal Dashboard
- Multi-line chart: one line per active SignalOperator (last 60 bars), with +/-confidence
  shaded bands
- Aggregate signal line: thicker line, confidence band wider
- Zero reference line at y=0
- No chart element uses #FFACE9 unless aggregate signal confidence < 0.40 (shows in
  warn-soft color)

1.8.4. P04 Position Detail
- Table: Symbol | Side | Qty | Avg Entry Price | Current Price | Unrealized P&L ($) |
  Unrealized P&L (%) | Weight (%)
- Color: green cells for positive P&L, red cells for negative P&L (no #FFACE9 in this table)
- Clicking a row opens an in-panel drill-down with the last 20 fill events for that symbol

1.8.5. P05 Order History
- Table: Timestamp | order_id | Symbol | Side | Type | Qty | Filled Qty | Fill Price | Status
- Color: filled=green, cancelled=grey, new=blue, partially_filled=orange
- Sortable and filterable by symbol and status

1.8.6. P06 Risk Audit
- Table: Timestamp | session_id | Rule ID | Verdict | Symbol | Measured Value | Threshold
- BLOCK rows: orange background; FLATTEN rows: alert-critical (#FFACE9) background;
  REDUCE rows: light orange
- Exportable as CSV via "Export" button

1.9. Modal Dialogs
1.9.1. Mode-switch confirm dialog: if user selects "Switch to Backtest" (configuration panel,
out of scope in MVP), a modal requires: "Type CONFIRM to switch mode" and confirmation
button. Session must be stopped before mode switch.
1.9.2. Session-stop confirm dialog: "Stop current session?" requires two-click confirm.
No auto-stop.
1.9.3. Modals are Dash dcc.ConfirmDialog or dbc.Modal components; they do not appear for
read-only navigation actions.

1.11. Dashboard Header Specification
1.11.1. The dashboard header is always visible regardless of active panel; it cannot be
hidden or minimized.
1.11.2. Header fields (left to right): X Quant X logo mark | session_id | mode badge
(PAPER / BACKTEST / LIVE) | RULESET_VERSION | session elapsed time | last refresh timestamp.
1.11.3. The mode badge background follows the aesthetics standard: PAPER=neutral,
BACKTEST=info-blue, LIVE=alert-critical (#FFACE9) to make live-mode unmistakably
distinguishable from paper and backtest modes.
1.11.4. Header is rendered outside the Dash dcc.Tabs component so it persists across
panel navigation without re-render flicker.

1.16. Conclusion
The X Quant X dashboard navigation and panel-display system gives a quantitative analyst an
unambiguous, observation-first view of the running paper-trading session. The monitoring-only
constraint is enforced by design: no panel imports or exposes execution-layer APIs. All six
panels auto-refresh at the per-bar interval; all state changes requiring confirmation are
guarded by modal dialogs (§1.9). The keyboard-shortcut model (§1.7.4, §1.12) ensures rapid
panel traversal without mouse dependency.
