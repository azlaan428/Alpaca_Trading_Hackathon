1.1. Abstract
This document defines the signal confidence score schema, the risk-gate verdict rules
(ALLOW / REDUCE / BLOCK / FLATTEN), regime-conditional scoring weights, the Kelly-fraction
position-sizing formula, and the performance attribution scoring schema for X Quant X. It is
the authoritative reference for all RiskOperator implementations.

1.2. Key Words
signal score, confidence, risk-gate verdict, ALLOW, REDUCE, BLOCK, FLATTEN, Kelly criterion,
position sizing, regime-conditional weights, Sharpe attribution, drawdown circuit-breaker,
RiskOperator, PerformanceOperator.

1.3. Executive Summary
X Quant X scores signals as float64 values in [-1, 1] with associated confidence in (0, 1].
Multiple signal operators' outputs are aggregated by SignalAggregationOperator into a single
aggregate score. RiskOperator evaluates the proposed allocation against the rule-set and emits
one of four verdicts: ALLOW (proceed), REDUCE (scale down to compliant size), BLOCK (do not
execute), or FLATTEN (close all positions). Position sizing uses fractional Kelly (25% of full
Kelly, capped at per-position and portfolio limits). Performance attribution scores each
SignalOperator's contribution to realized Sharpe.

1.4. Key Findings
1.4.1. The signal score is always in [-1, 1]; +1 = maximum long signal, -1 = maximum short
signal, 0 = neutral. No signal score can exceed this range. Any operator producing an
out-of-range score triggers ValidationOperator immediately.
1.4.2. The risk-gate verdict is the sole gate for order execution. No order bypasses
RiskOperator. Four verdicts are mandatory and must all be handled by every downstream
consumer.
1.4.3. The Kelly criterion optimal fraction f* = p - q/b is always applied as a fractional
form: f = κ·f* where κ = 0.25 (25% of full Kelly). An additional hard cap f ≤ 0.20 per
position and portfolio drawdown circuit-breaker (15% from equity peak → FLATTEN) constrain
the output.
1.4.4. Regime-conditional weights w_i(r) scale each SignalOperator's contribution to the
aggregate: in low-volatility regimes (R01, R11) momentum signals receive higher weight; in
high-uncertainty regimes (R05, R07) risk-averse signals receive higher weight.
1.4.5. Performance attribution partitions realized P&L by SignalOperator (which operators
contributed), regime label (in which regime state P&L was earned), and time period.

1.5. Philosophical Preamble
A scoring system for a compliance test bench and a scoring system for a trading platform share
one principle: the verdict must be explainable. In X Quant X, every risk-gate verdict must be
accompanied by the specific rule that triggered it, the measured value that violated the
threshold, and the threshold itself — logged in the audit trail so that every REDUCE or BLOCK
is auditable after the fact. A trading decision system whose verdicts cannot be explained is a
liability, not a feature.

1.6. Signal Score Schema

1.6.1. Score Type and Range
Signal score type: float64 ∈ [-1, 1]. +1 = maximum long conviction, -1 = maximum short
conviction, 0 = no directional view.

1.6.2. Confidence Type and Range
Confidence type: float64 ∈ (0, 1]. 1.0 = maximum confidence. Values ≤ 0 are invalid and
trigger ValidationOperator.

1.6.3. Aggregate Score Formula
Aggregate score formula: S = Σ_i (c_i · s_i) / Σ_i c_i. Confidence-weighted mean of all
active SignalOperator outputs. Cite: prompt_patterns.md §5.1.

1.6.4. Regime-Conditional Weights
Regime-conditional weights: w_i(r) for SignalOperator i in regime r. The
SignalAggregationOperator multiplies each signal by the regime-appropriate weight before
aggregation. Weights are declared in config/regimes.toml per regime ID (R01–R12).

1.6.5. Score Bounds Invariant
Score bounds invariant: |S| ≤ 1.0. Proven in prompt_patterns.md §5.1. Any score outside
this range is a validation error.

1.7. Risk-Gate Verdict Rules

1.7.1. Verdict Enum
Verdict enum: ALLOW, REDUCE, BLOCK, FLATTEN. These are the only valid output values of
RiskOperator.process(). No alternative verdicts may be defined.

1.7.2. ALLOW
ALLOW: proposed allocation passes all hard and soft limits. ExecutionOperator proceeds with
the full proposed allocation.

1.7.3. REDUCE
REDUCE: proposed allocation violates a soft limit. ExecutionOperator scales the proposed
position to the maximum compliant size. The scale factor and the violated rule are logged
to AUDIT_LOGS/.

1.7.4. BLOCK
BLOCK: proposed allocation violates a hard limit. ExecutionOperator does not submit any order
for the blocked symbol this bar. The violated rule and measured value are logged.

1.7.5. FLATTEN
FLATTEN: portfolio risk breach detected (e.g. maximum drawdown exceeded). ExecutionOperator
submits market-sell orders for all open positions. The trigger rule (e.g. max_drawdown = 0.15
exceeded) is logged.

1.7.6. Mandatory Hard Limits (BLOCK Triggers)
- Per-position concentration: qty > 0.20 × portfolio_equity → BLOCK (REDUCE to 0.20 × equity)
- Gross leverage: > 1.0 (paper MVP has no margin) → BLOCK
- Regime-conditional: in regimes R04 (bear-capitulation) or R07 (macro-shock), all new long
  positions are BLOCKED unless aggregate signal confidence > 0.85

1.7.7. Mandatory FLATTEN Trigger
Portfolio drawdown from equity peak > 0.15 (15%) → FLATTEN all positions immediately.

1.7.8. Soft Limits (REDUCE Triggers)
- Sector exposure > 0.35 × portfolio_equity for any single sector → REDUCE to 0.35 × equity
- Single symbol P&L contribution > 0.30 of total portfolio exposure → REDUCE

1.8. Position Sizing

1.8.1. Kelly Optimal Fraction
Kelly optimal fraction: f* = p - q/b = p - (1-p)/b. Where p = estimated win probability
(from signal confidence), b = estimated win/loss payoff ratio (from historical backtest or
regime-specific prior). Cite: prompt_patterns.md §5.2.

1.8.2. Fractional Kelly
Fractional Kelly: f = κ · f* where κ = 0.25. This reduces exposure by 75% from full Kelly
to account for estimation error in p and b.

1.8.3. Hard Per-Position Cap
Hard per-position cap: f ≤ 0.20 regardless of Kelly output.

1.8.4. Evaluation Order
All f computations occur inside PortfolioOperator before RiskOperator evaluation.
RiskOperator may further REDUCE the output of PortfolioOperator.

1.9. Performance Attribution Schema

1.9.1. Per-SignalOperator Sharpe Contribution
Per-SignalOperator Sharpe contribution: Sharpe_i = mean(r_i) / std(r_i) × sqrt(252) where
r_i is the series of bar returns attributable to SignalOperator i's trades.

1.9.2. Regime-Tagged Attribution
Regime-tagged attribution: total P&L segmented by regime_id (R01–R12) and time period for
each session.

1.9.3. Storage and Display
All attribution data is stored in PortfolioSnapshot.signal_attribution (JSON field) and
queried by the dashboard's attribution stacked-area chart.

1.14. Conclusion
The scoring rules define a complete, auditable decision pipeline from signal confidence score
through risk-gate verdict to position sizing. Every verdict is logged with its triggering rule
and measured value. The 25% fractional Kelly with hard caps provides conservative,
drawdown-bounded sizing.
