1.1. Abstract
This document specifies the core data structures and algorithms underlying the X Quant X
operator pipeline and trading engines, providing the concrete representations and time/space
complexity analysis required by 005_xquantx_coding_standards.txt §1.8 for every Operator
defined in 006_xquantx_scaffolding.txt.

1.2. Key Words
data structure, algorithm, complexity analysis, OHLCV bar, tick, order, position, regime
state, Kalman filter, HMM, signal aggregation, Kelly criterion, circular buffer, operator
DAG, financial time-series.

1.3. Executive Summary
X Quant X represents financial time-series data as schema-first immutable value objects
(OHLCVBar, Tick, Order, Position). Rolling indicator windows use circular buffers for O(1)
append/evict. The operator dependency graph is a directed acyclic graph (DAG) traversed in
topological order. Regime state carries a probability vector (never a single label) updated
via Bayesian posteriors and Kalman filter steps. Signal aggregation is confidence-weighted.
Position sizing uses fractional Kelly with a hard cap. Portfolio optimization uses
mean-variance or risk-parity depending on regime.

1.4. Key Findings
1.4.1. All canonical data types (OHLCVBar, Tick, Order, Position, RegimeState, Signal) are
defined in schemas/ as language-neutral types first; language-specific implementations
derive from these schemas.
1.4.2. Rolling indicator computation (RSI, MACD, ATR, Bollinger) uses a CircularBuffer of
capacity W (window size), yielding O(1) append, O(W) initialization, O(W) computation per
bar.
1.4.3. The operator dependency graph is a DAG; topological sort determines execution order.
Adding a cycle is a hard error caught at initialization time (O(V+E) cycle detection).
1.4.4. The Kalman filter update step (state vector update + covariance update) is O(n^2) in
state dimension n. For a regime state vector of dimension K (number of regime types,
typically <= 12), this is effectively constant time per bar.
1.4.5. Confidence-weighted signal aggregation is O(N) where N is the number of active
SignalOperators.
1.4.6. The temporal leakage invariant is enforced by the data structure: every OHLCVBar and
Tick carries a timestamp; the pipeline asserts strictly_increasing_timestamps(bars) before
any FeatureOperator processes them.

1.5. Philosophical Preamble
Complexity analysis is not academic decoration; it is the concrete evidence that a regime
inference pass over 10,000 bars completes within the backtest time budget, and it is
required documentation under 005_xquantx_coding_standards.txt §1.8. An ALLOW/REDUCE/BLOCK/
FLATTEN verdict from a RiskOperator is only as trustworthy as the data structures feeding
it are bounded, schema-validated, and free of hidden mutable state.

1.6. Core Data Structures

1.6.1. OHLCVBar (canonical OHLCV bar)
Immutable value object: symbol (str), timestamp (int64, UTC nanoseconds since epoch), open
(float64), high (float64), low (float64), close (float64), volume (float64), vwap (float64),
trade_count (int64), timeframe (str: "1m"|"5m"|"1h"|"1d"). Space: O(1) per bar.
Time-series: O(T) for T bars. Field invariants: high >= open, high >= close, high >= low;
low <= open, low <= close; volume >= 0; all prices > 0. A violated invariant triggers
ValidationOperator.

1.6.2. Tick
Immutable value object: symbol (str), timestamp (int64, UTC nanoseconds), price (float64),
size (float64), exchange (str), conditions (List[str]). Space: O(1) per tick.

1.6.3. Order (paper-trading order)
Immutable value object (once submitted): order_id (str, UUID), client_order_id (str),
symbol (str), side ("buy"|"sell"), type ("market"|"limit"|"stop"|"stop_limit"), qty
(float64), filled_qty (float64), limit_price (float64|None), stop_price (float64|None),
status ("new"|"partially_filled"|"filled"|"cancelled"|"expired"), submitted_at (int64),
filled_at (int64|None). Status transitions are append-only: "new" -> "partially_filled"
-> "filled" or "cancelled".

1.6.4. Position
Mutable value object (updated on each fill): symbol (str), qty (float64), avg_entry_price
(float64), current_price (float64), unrealized_pl (float64), unrealized_plpc (float64),
side ("long"|"short"). Updated atomically per fill event.

1.6.5. RegimeState (regime probability distribution)
Immutable snapshot per bar: timestamp (int64), regime_id (str: most probable regime label
from 027_xquantx_regime_archetypes.txt), regime_probabilities (Dict[str, float64]: must sum
to 1.0 +/- 1e-9), confidence (float64: 1 - normalized entropy), kalman_state_vector
(List[float64]), kalman_covariance_matrix (List[List[float64]]). Cite:
high_level_proofs/high_level_kalman_filter_states_capital_allocation_proof.tex.

1.6.6. Signal
Immutable value object: operator_id (str), symbol (str), timestamp (int64), score (float64
in [-1, 1]), confidence (float64 in (0, 1]), regime_id (str), version (str).

1.6.7. CircularBuffer (rolling window)
Fixed-capacity ring buffer: capacity W (window size). Append: O(1). Evict oldest: O(1).
Full iteration: O(W). Used for all rolling indicator computations (RSI, MACD, ATR,
Bollinger, OBV). Space: O(W).

1.6.8. Operator DAG
Directed acyclic graph of Operators with typed edges (output schema -> input schema).
Topological sort determines execution order. O(V+E) traversal per bar, where V = number of
operators, E = number of dependencies. Cycle detection at initialization: O(V+E).

1.6.9. AllocationVector
A mapping symbol -> target_weight (float64 in [-1, 1]) where weights sum to <= 1.0.
Produced by PortfolioOperator; consumed by ExecutionOperator.

1.7. Core Algorithms

1.7.1. Kalman Filter Update Step
State prediction: x_hat(t|t-1) = A * x_hat(t-1|t-1).
Covariance prediction: P(t|t-1) = A * P(t-1|t-1) * A^T + Q.
Innovation: y(t) = z(t) - H * x_hat(t|t-1).
Innovation covariance: S(t) = H * P(t|t-1) * H^T + R.
Kalman gain: K(t) = P(t|t-1) * H^T * S(t)^(-1).
State update: x_hat(t|t) = x_hat(t|t-1) + K(t) * y(t).
Covariance update: P(t|t) = (I - K(t) * H) * P(t|t-1).
Time complexity: O(n^2) where n is state dimension. Cite:
high_level_proofs/high_level_kalman_filter_states_capital_allocation_proof.tex.

1.7.2. Bayesian Regime Posterior Update
P(r_k | x_t) = P(x_t | r_k) * P(r_k) / sum_j P(x_t | r_j) * P(r_j).
With regime transition matrix A: P(r_k at t) = sum_j A_jk * P(r_j at t-1 | x_{t-1}).
Time complexity: O(K^2) where K is number of regimes (<= 12). Cite:
alpaca_trading_agents_concept/prompt_patterns.md §5.4.

1.7.3. Confidence-Weighted Signal Aggregation
S = sum_i (c_i * s_i) / sum_i c_i.
Aggregate uncertainty: U = 1 - sum_i c_i^2 / (sum_i c_i)^2 * N.
Bounds proof: |S| <= 1 since |s_i| <= 1 and c_i > 0.
Time complexity: O(N) where N is number of active SignalOperators. Cite:
alpaca_trading_agents_concept/prompt_patterns.md §5.1.

1.7.4. Fractional Kelly Position Sizing
f* = p - q/b (Kelly optimal fraction). Applied as f = kappa * f* where kappa in (0, 1]
(fractional Kelly). Hard cap: f <= f_max (per 028_xquantx_risk_ruleset.txt).
Time complexity: O(1). Cite: alpaca_trading_agents_concept/prompt_patterns.md §5.2.

1.7.5. Rolling Indicator (e.g. RSI-14) via CircularBuffer
Initialize CircularBuffer(capacity=14). Per bar: append close price, evict oldest if full,
compute RSI over buffer contents. Complexity: O(14) = O(W) per bar (constant for fixed
window). Total for T bars: O(T * W).

1.7.6. DAG Topological Sort (Kahn's algorithm)
Compute in-degree for each operator node. Queue all zero-in-degree nodes. While queue
non-empty: dequeue u, append to order, for each v in u's successors: decrement
in-degree(v), if zero enqueue v. If len(order) < V: cycle detected (hard error).
Time: O(V+E). Space: O(V).

1.8. Complexity Analysis
| Algorithm                  | Time            | Space    | Note                          |
|----------------------------|-----------------|----------|-------------------------------|
| Kalman filter update       | O(n^2) per bar  | O(n^2)   | n = state dimension (<= 12)   |
| Bayesian regime update     | O(K^2) per bar  | O(K)     | K = regime count (<= 12)      |
| Signal aggregation         | O(N) per bar    | O(N)     | N = active operators          |
| Rolling indicator          | O(W) per bar    | O(W)     | W = window size               |
| DAG topological sort       | O(V+E) per init | O(V)     | One-time at startup           |
| Kelly sizing               | O(1) per signal | O(1)     |                               |
| Portfolio optimization (MV)| O(n^3) per dec  | O(n^2)   | n = number of assets          |

1.11. Risk and Mitigation Table
| Risk | Likelihood | Impact | Mitigation |
|------|-----------|--------|------------|
| NaN propagation from Kalman step corrupting RegimeState | Low | Critical | §1.7.1: all matrix operations assert finite output before propagation |
| Temporal leakage (future data in feature computation) | Medium | Critical | §1.4.6: pipeline asserts strictly_increasing_timestamps before FeatureOperator |
| Regime probability vector not summing to 1.0 | Medium | High | ValidationOperator checks sum +/- 1e-9 on every RegimeState |
| CircularBuffer overflow corrupting rolling indicator | Low | High | Fixed-capacity enforced; insertion count <= capacity is asserted at init |
