1.1. Abstract
This document specifies visualization/screenshot standards for VoiceGate's specification
corpus, elaborating the original baseline directive into concrete rules for image format,
captioning, and cross-referencing, and binding all such images to the palette and visual
identity defined in voice_processing_specifications/002_voicegate_aesthetics.txt.

1.2. Key Words
visualization, screenshot, PNG, caption, cross-reference, aesthetic compliance, Risk Report,
calibration chart, VoiceGate.

1.3. Executive Summary
Every screenshot included in any VoiceGate specification document is a single image per
instance, in PNG format only, accompanied by a clear caption and an explicit reference to the
section of text it illustrates, and must visually conform to the palette/typography rules in
voice_processing_specifications/002_voicegate_aesthetics.txt. Typical illustrated instances
are Test Bench launch screens, Call Review transcript-with-verdict-badge views, and Risk
Report judge-calibration charts.

1.4. Key Findings
1.4.1. Exactly one image is used per illustrated instance (no multi-panel composite images),
per the preserved baseline directive.
1.4.2. PNG is the only accepted image format, per the preserved baseline directive, chosen
for lossless quality suited to UI screenshots and calibration charts containing text and
sharp geometric shapes.
1.4.3. Every included screenshot requires a caption and an explicit reference to the relevant
section(s) of the surrounding text, per the preserved baseline directive.
1.4.4. Screenshots must reflect the aesthetic standards document
(voice_processing_specifications/002_voicegate_aesthetics.txt), i.e. actual palette
variants, typography, and visual language, not placeholder or inconsistent styling.
1.4.5. This document governs documentation-embedded screenshots specifically; it does not
redefine UI layout (voice_processing_specifications/004_voicegate_ui_navigation.txt) or
palette values, both of which remain governed by their own documents.

1.5. Philosophical Preamble
A screenshot embedded in a specification document is a claim about what the product actually
looks like; an uncaptioned or unreferenced image is a claim nobody can verify or locate. This
matters more, not less, in a compliance test bench: a Risk Report calibration chart is itself
evidence, and evidence that cannot be traced to the text it supports is not usable evidence.

1.6. Original Baseline Directive (Preserved Verbatim)
"Follow aesthetic standards document -- single image per instance, and in PNG format only.
All relevant screenshots must be included in the game specification document, with clear
captions and references to the relevant sections of the text."

1.7. Screenshot Format Rule
1.7.1. PNG format only (per Section 1.6); no JPEG, GIF, WEBP, BMP, or other raster/vector
formats.
1.7.2. Exactly one image per illustrated instance; composite/multi-panel images are not
used, per Section 1.6.

1.8. Captioning and Section-Reference Rule
1.8.1. Every embedded screenshot carries a caption describing what it depicts.
1.8.2. Every embedded screenshot's caption includes an explicit reference to the section(s)
of the surrounding document text that it illustrates (e.g. "See Section 1.7, Risk Report
judge-calibration chart").

1.9. Aesthetic Compliance Rule
Every screenshot must depict the product rendered per
voice_processing_specifications/002_voicegate_aesthetics.txt's approved palette variant(s)
and typography; a screenshot depicting an unapproved or placeholder visual style does not
satisfy this standard and must not be included.

1.10. Applicability
This standard applies to all specification documents in `voice_processing_specifications/`
that embed screenshots, including but not limited to
voice_processing_specifications/004_voicegate_ui_navigation.txt (Test Bench/Call Review
screen layouts) and voice_processing_specifications/002_voicegate_aesthetics.txt
(palette/typography examples), and to any future document that embeds a screenshot (e.g. a
Risk Report calibration-chart export).
