1.1. Abstract
This document defines the per-session and per-strategy run statistics produced by
PerformanceOperator after each trading session. It specifies the metric definitions,
computation formulas, attribution decomposition rules, and the CSV export format for
cross-session analysis.

1.2. Key Words
run statistics, P&L, Sharpe ratio, Sortino ratio, Calmar ratio, max drawdown, signal
attribution, regime attribution, risk-gate trigger frequency, PerformanceOperator,
PerformanceSnapshot, session summary.

1.3. Executive Summary
At the end of each session (paper or backtest), PerformanceOperator computes a full set of
risk-adjusted performance metrics: total P&L, daily returns, Sharpe ratio, Sortino ratio,
Calmar ratio, and maximum drawdown. Attribution splits P&L by SignalOperator and by regime
label. Risk-gate trigger frequency reports how often each rule (CONC-001, LEV-001, etc.)
fired during the session. All statistics are exported as CSV to
AUDIT_LOGS/{session_id}_stats.csv.

1.4. Key Findings
1.4.1. Sharpe ratio = mean(daily returns) / std(daily returns) x sqrt(252) where returns
are computed from PortfolioSnapshot.daily_pl / equity(t-1). Bootstrap 95% CI is computed
over 1,000 resampled return series (per 026_xquantx_variance_terminology.txt §1.8).
1.4.2. Sortino ratio uses downside deviation (std of negative returns only). Calmar ratio =
annualized return / max drawdown.
1.4.3. Signal attribution: for each SignalOperator, its Sharpe contribution is computed as
the Sharpe of the sub-series of daily returns attributable to trades initiated by that
operator's signals.
1.4.4. Regime attribution: total P&L segmented by regime_id (R01-R12) for each session.
1.4.5. Risk-gate trigger frequency: for each rule ID (CONC-001 through EXEC-001), count of
BLOCK/REDUCE/FLATTEN verdicts during the session.

1.5. Philosophical Preamble
A performance statistic is only trustworthy if it traces back to an auditable, reproducible
record. X Quant X's run statistics are derived exclusively from PortfolioSnapshot and the
structured fill log — no statistic is hand-entered or computed from an untracked source. A
Sharpe ratio that cannot be reproduced from the session's raw daily equity series is not a
Sharpe ratio; it is noise dressed as signal.

1.6. Metric Definitions
| Metric | Formula | Note |
|--------|---------|------|
| Total P&L | equity(end) - equity(start) | Net of all fills |
| Daily return (r_t) | (equity(t) - equity(t-1)) / equity(t-1) | Per bar (1-day bars) |
| Annualized return | mean(r_t) x 252 | Assumes 252 trading days/year |
| Sharpe ratio | mean(r_t) / std(r_t) x sqrt(252) | 95% CI via bootstrap (1,000 samples) |
| Sortino ratio | mean(r_t) / downside_std(r_t) x sqrt(252) | downside_std = std(r_t[r_t < 0]) |
| Calmar ratio | annualized_return / max_drawdown | max_drawdown from peak watermark |
| Max drawdown | max((peak - trough) / peak) over session | |
| Hit rate | count(positive daily returns) / count(daily returns) | |
| Avg win / Avg loss | mean(r_t[r_t>0]) / |mean(r_t[r_t<0])| | |
| Risk-adjusted return | Sharpe x std(r_t) x sqrt(252) | = annualized return (identity check) |

Note: std = 0 => Sharpe = 0.0 (not NaN or Inf); unit test asserts finite output.

1.7. Signal Attribution
1.7.1. For each SignalOperator i, compute the sub-series of daily returns r_i_t = daily_pl
attributable to trades that were initiated in response to SignalOperator i's signal on that
bar.
1.7.2. Sharpe_i = mean(r_i_t) / std(r_i_t) x sqrt(252).
1.7.3. Attribution share_i = |Sharpe_i| / sum_j |Sharpe_j|. ValidationOperator asserts
sum = 1.0 +/- 1e-6.
1.7.4. All attribution data stored in PerformanceSnapshot.signal_attribution (JSON dict:
operator_id -> {sharpe, share}).

1.8. Regime Attribution
1.8.1. For each regime_id R in {R01, ..., R12}, compute the total P&L earned during bars
when regime_id == R.
1.8.2. Regime P&L% = regime_pl / total_pl x 100%.
1.8.3. All attribution data stored in PerformanceSnapshot.regime_attribution (JSON dict:
regime_id -> {pl, pl_pct}).
1.8.4. Dashboard visualization: stacked-area chart of cumulative P&L colored by regime_id
(P02 Regime Monitor panel; see 004_xquantx_ui_navigation.txt).

1.9. Risk-Gate Trigger Frequency
1.9.1. For each rule_id (CONC-001, LEV-001, REGM-001, DLOSS-001, SECT-001, CONF-001,
ENT-001, ENT-002, DD-001, EXEC-001), count the number of REDUCE, BLOCK, and FLATTEN
verdicts triggered during the session.
1.9.2. Stored in PerformanceSnapshot.risk_gate_triggers (JSON dict: rule_id ->
{reduce_count, block_count, flatten_count}).
1.9.3. Dashboard visualization: Risk Audit panel (P06) shows this as a bar chart grouped by
rule_id.

1.10. CSV Export Format
The session summary CSV (AUDIT_LOGS/{session_id}_stats.csv) has the following columns:
session_id, session_date, mode, symbol_count, bar_count, total_pl, daily_return_mean,
daily_return_std, sharpe (P50), sharpe_ci_low, sharpe_ci_high, sortino, calmar,
max_drawdown, hit_rate, avg_win, avg_loss, ruleset_version, regime_attribution_json,
signal_attribution_json, risk_gate_triggers_json.

1.14. Conclusion
X Quant X's run statistics model gives engineers and portfolio managers an auditable,
PortfolioSnapshot-derived view of each session's performance, with Sharpe/Sortino/Calmar
risk-adjustment, signal and regime attribution, and risk-gate trigger frequency — all
exported to CSV for cross-session trend analysis.
