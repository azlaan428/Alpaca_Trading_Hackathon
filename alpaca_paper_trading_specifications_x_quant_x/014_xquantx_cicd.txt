1.1. Abstract
This document defines the CI/CD pipeline for X Quant X across all four implementation
languages (Python, Go, C++, Rust). It specifies pipeline stages, per-language test runners,
coverage gates, lint and type-check stages, build-artifact versioning, and the GitHub Actions
workflow layout.

1.2. Key Words
CI/CD, GitHub Actions, pytest, go test, ctest, cargo test, coverage gates, lint, mypy,
golangci-lint, clang-tidy, clippy, build matrix, artifact versioning, four-language,
Shadow CI gate.

1.3. Executive Summary
X Quant X CI/CD runs in GitHub Actions with parallel jobs per language layer. The pipeline
stages are: (1) lint + type-check for each language; (2) unit tests with coverage gate;
(3) integration tests; (4) simulation tests (backtest e2e); (5) performance tests;
(6) Shadow CI gate (Dry-run comparison). No merge to main is permitted unless all six stages
pass for all four languages. Build artifacts are versioned with the short git commit SHA.

1.4. Key Findings
1.4.1. Four parallel language jobs: Python, Go, C++, Rust. Each job runs its own lint,
type-check, unit test, and coverage gate independently.
1.4.2. Coverage gates: 100% branch coverage on all Operator implementations in Python
(coverage.py), and per-language equivalents for Go, C++, Rust (enforced per
009_xquantx_unit_tests.txt).
1.4.3. Lint and type-check stages: ruff + mypy --strict (Python), golangci-lint (Go),
clang-tidy (C++), clippy --deny warnings (Rust). Any lint failure blocks the merge.
1.4.4. The integration and simulation test stages run after all four language unit test
stages pass (sequential dependency).
1.4.5. The Shadow CI gate is the last mandatory CI step; it runs the Dry-run comparison
against a pinned baseline (per 008_xquantx_testing.txt §1.10).

1.5. Philosophical Preamble
A pipeline is where this corpus's other promises (100% branch coverage on operators,
mandatory Shadow CI gate, multi-language correctness) stop being aspirations and start being
mechanically enforced facts about every single change. This document exists so that no
quality standard declared elsewhere in this corpus is left to depend on a human remembering
to check it manually.

1.6. GitHub Actions Workflow Layout
The CI pipeline is defined in .github/workflows/ci.yml with the following jobs structure:

    jobs:
      lint-python:
        runs-on: ubuntu-latest
        steps: checkout -> setup Python 3.14 -> pip install -r requirements-dev.txt
               -> ruff check src/python/ tests/python/
               -> mypy --strict src/python/

      lint-go:
        runs-on: ubuntu-latest
        steps: checkout -> setup Go (pinned version from go.mod) -> go mod download
               -> golangci-lint run ./...

      lint-cpp:
        runs-on: ubuntu-latest
        steps: checkout -> conan install -> cmake configure
               -> clang-tidy -p build/ src/cpp/

      lint-rust:
        runs-on: ubuntu-latest
        steps: checkout -> rustup show (use rust-toolchain.toml)
               -> cargo clippy -- -D warnings

      test-python:
        needs: [lint-python]
        steps: ... -> pytest tests/python/ --cov=src/python --cov-branch
                    -> coverage report --fail-under=100

      test-go:
        needs: [lint-go]
        steps: ... -> go test ./... -coverprofile=coverage.out -covermode=atomic

      test-cpp:
        needs: [lint-cpp]
        steps: ... -> cmake --build build --target tests -> ctest --test-dir build

      test-rust:
        needs: [lint-rust]
        steps: ... -> cargo test --all-features
                    -> cargo tarpaulin --out Xml

      test-integration:
        needs: [test-python, test-go, test-cpp, test-rust]
        steps: ... -> pytest tests/python/integration/ -v

      test-simulation:
        needs: [test-integration]
        steps: ... -> pytest tests/python/simulation/ -v
                    -> pytest tests/python/simulation/test_temporal_leakage.py -v

      test-performance:
        needs: [test-simulation]
        steps: ... -> pytest tests/python/performance/ --benchmark-autosave

      shadow-ci:
        needs: [test-performance]
        steps: ... -> pytest tests/shadow/test_shadow_ci.py -v

1.7. Per-Language Test Stage Details
1.7.1. Python: pytest with --cov=src/python --cov-branch. Coverage report fails build if
branch coverage < 100% for any operator file. Hypothesis tests run with 500 examples
(configurable via HYPOTHESIS_MAX_EXAMPLES env var).
1.7.2. Go: go test ./... with -race flag (race detector enabled). go cover with
-covermode=atomic. Coverage threshold is enforced via a script checking go cover output.
1.7.3. C++: ctest in Release build mode. Google Test XML output is published as CI artifact.
clang-tidy runs with -warnings-as-errors for all X Quant X source files.
1.7.4. Rust: cargo test --all-features. cargo tarpaulin generates coverage XML. clippy with
-- -D warnings ensures zero lint warnings.

1.8. Lint and Type-Check Gates
| Language | Lint tool              | Type check              | Failure behavior |
|----------|------------------------|-------------------------|-----------------|
| Python   | ruff                   | mypy --strict           | Block merge     |
| Go       | golangci-lint          | native (go vet)         | Block merge     |
| C++      | clang-tidy             | clang-analyzer          | Block merge     |
| Rust     | clippy --deny warnings | native (rustc)          | Block merge     |

1.9. Coverage Gates
| Language | Tool         | Gate                                | Scope                        |
|----------|--------------|-------------------------------------|------------------------------|
| Python   | coverage.py  | 100% branch on Operator files       | src/python/operators/**/*.py |
| Go       | go cover     | 80% total (no per-package gate yet) | internal/ packages           |
| C++      | gcov/lcov    | 80% line coverage                   | src/cpp/src/**/*.cpp         |
| Rust     | tarpaulin    | 80% line coverage                   | src/rust/src/**/*.rs         |

1.10. Build-Artifact Versioning
1.10.1. All build artifacts are labeled with the short git commit SHA:
xquantx-python-{SHA}.tar.gz, xquantx-go-{SHA}.tar.gz, etc.
1.10.2. Docker images (if built) are tagged:
ghcr.io/xquantx/xquantx-platform:{SHA} and ghcr.io/xquantx/xquantx-platform:latest.
1.10.3. The RULESET_VERSION from config/risk_rules.toml is included in the artifact
metadata and logged in AUDIT_LOGS/ at session start.

1.13. Risk and Mitigation Table
| Risk                                                                    | Likelihood | Impact | Mitigation                                                                                                          |
|-------------------------------------------------------------------------|------------|--------|---------------------------------------------------------------------------------------------------------------------|
| C++ or Rust CI steps skipped due to slow build                          | Medium     | High   | CI stages are mandatory (no skip); cache Conan packages and Cargo registry between runs                             |
| Shadow CI gate becomes stale due to market structure change             | High       | Medium | Baseline in tests/baselines/ is a versioned file; update deliberately when operator behavior intentionally changes  |
| Python 100% branch coverage gate too strict (causes test proliferation) | Medium     | Medium | Gate applies only to src/python/operators/**; dashboard/ and scripts/ are exempt                                    |
| CI API rate limit on Alpaca sandbox integration tests                   | Medium     | Low    | Sandbox tests gated on RUN_SANDBOX_TESTS=1; default CI does not run them                                            |
