1.1. Abstract
This document defines the uncertainty, variance, and stochastic terminology used consistently
throughout the X Quant X specification corpus and codebase. It distinguishes epistemic
uncertainty (model uncertainty, reducible with more data) from aleatoric uncertainty (market
randomness, irreducible), defines Monte Carlo sampling conventions, explains bootstrap
confidence intervals for backtest metrics, and establishes seed management rules for
reproducibility.

1.2. Key Words
epistemic uncertainty, aleatoric uncertainty, Monte Carlo, bootstrap, confidence interval,
seed management, reproducibility, variance decomposition, market noise, regime sampling,
signal uncertainty, sigma, confidence band.

1.3. Executive Summary
X Quant X distinguishes two types of uncertainty throughout its pipeline: epistemic (our
ignorance of the true model, reducible with better data/models) and aleatoric (irreducible
market randomness). Signal confidence scores represent epistemic uncertainty about the signal
direction. Regime entropy represents aleatoric uncertainty about market state. Monte Carlo
methods are used for backtest distribution estimation, stress testing, and
regime-transition simulation. All random processes in the platform use seeded RNG for
reproducibility.

1.4. Key Findings
1.4.1. Epistemic uncertainty: the uncertainty in a model's estimate that would be reduced if
more (or better) data were available. In X Quant X, signal confidence scores are epistemic
estimates of how sure a SignalOperator is about its directional prediction.
1.4.2. Aleatoric uncertainty: the inherent randomness of the market that cannot be reduced
regardless of model sophistication. Regime entropy is partly aleatoric — regime transitions
are stochastic even with perfect feature information.
1.4.3. Monte Carlo sampling in X Quant X is used for: (a) backtest distribution estimation
(sample many random walk-forward windows), (b) stress testing (sample adverse scenarios),
(c) regime-transition simulation (sample from transition matrix A). All Monte Carlo runs use
an integer seed declared in config/backtest.toml.
1.4.4. Bootstrap confidence intervals: for backtest performance metrics (Sharpe, Sortino,
Calmar), the platform computes 95% bootstrap confidence intervals over 1,000 resampled
return series, so that reported metrics include uncertainty bands.
1.4.5. Reproducibility invariant: any Monte Carlo or bootstrap run, given the same seed,
input data, and operator versions, must produce byte-identical results.

1.5. Philosophical Preamble
Variance in a trading system is not a problem to be eliminated; it is a signal to be
quantified. A system that reports a Sharpe of 1.8 without a confidence interval is expressing
false certainty. A system that never uses Monte Carlo simulation to stress-test its
regime-transition assumptions is optimistic by construction. This document's purpose is to
give every operator, analyst, and reviewer a shared vocabulary for expressing, measuring, and
bounding the uncertainty that is inherent to any quantitative model operating in a partially
observable market.

1.6. Epistemic vs Aleatoric Uncertainty
1.6.1. Epistemic uncertainty: model uncertainty. Example: a SignalOperator's confidence score
of 0.65 means the model is 65% confident in its directional prediction, given the current
feature vector. This confidence is epistemic — more historical data or a better model could
improve it.
1.6.2. Aleatoric uncertainty: market randomness. Example: even a perfect
MarketRegimeOperator cannot eliminate the inherent stochasticity of regime transitions. The
regime entropy U_t captures this.
1.6.3. Decomposition: total uncertainty = epistemic + aleatoric. The platform tracks both
separately: signal confidence captures epistemic uncertainty; regime entropy captures
aleatoric uncertainty.
1.6.4. Practical implication: when both epistemic and aleatoric uncertainty are high (low
signal confidence AND high regime entropy), RiskOperator applies a conservative REDUCE or
BLOCK regardless of signal score magnitude.

1.7. Monte Carlo Sampling
1.7.1. Backtest distribution: to avoid overfitting to a single historical window, the platform
samples N_MC random walk-forward windows of length W from the historical dataset, runs a
full backtest in each, and reports the distribution of Sharpe, Sortino, Calmar, and max
drawdown.
1.7.2. Stress testing: the platform samples K adverse scenarios by drawing regime sequences
with high R04/R07 probability from the transition matrix and computing portfolio performance
under each.
1.7.3. Regime-transition simulation: transition matrix A is sampled forward T steps to
simulate probable regime paths for scenario planning.
1.7.4. Seeds: all Monte Carlo runs declare MONTE_CARLO_SEED in config/backtest.toml.
Reproducibility invariant: same seed + same data + same operator versions = same results.
1.7.5. N_MC default: 1,000 samples. W default: 252 bars (approximately 1 trading year for
daily bars). These are configurable in config/backtest.toml.

1.8. Bootstrap Confidence Intervals
1.8.1. For each performance metric M (Sharpe, Sortino, Calmar, max drawdown), the bootstrap
confidence interval at 95% level is computed by:
   (a) Sample 1,000 resampled return series (with replacement) from the backtest return
       series.
   (b) Compute M on each resampled series.
   (c) Report [5th percentile, 95th percentile] as the 95% CI.
1.8.2. Reported metrics always include the 95% CI: e.g.
"Sharpe = 1.42 [0.87, 1.95] (95% CI, 1000 bootstrap samples)".
1.8.3. Any backtest report that omits confidence intervals is non-compliant with this
specification.

1.9. Seed Management
1.9.1. All random processes in the platform (Monte Carlo, bootstrap, regime initialization
noise) use a single integer seed per session, declared in config/backtest.toml
(MONTE_CARLO_SEED) for backtest sessions and in config/paper_trading.toml (SESSION_SEED)
for paper-trading sessions.
1.9.2. The seed is logged as part of the session metadata in AUDIT_LOGS/ so that any result
is exactly reproducible given the same configuration.
1.9.3. No operator uses the language default random source (Python random.random(), Go
math/rand without seeding, C++ std::rand). All use the seeded RNG wrapper from
xquantx.utils.rng.

1.10. Variance Decomposition
1.10.1. Portfolio return variance is decomposed into: systematic variance (correlated with
regime), factor variance (loading on common factors: market, sector, rate), and idiosyncratic
variance (uncorrelated with any factor).
1.10.2. The PerformanceOperator computes this decomposition and includes it in
PerformanceSnapshot.variance_decomposition.
1.10.3. A portfolio with high idiosyncratic variance has poorly diversified positions; this is
a REDUCE trigger per 028_xquantx_risk_ruleset.txt.

1.15. Conclusion
This file provides a single vocabulary and equation contract for all uncertainty-driven
modeling in X Quant X, reducing ambiguity across implementation, QA, and risk analytics,
and preserving reproducibility of any backtest or paper-trading run given its recorded seed
and configuration.

1.16. Glossary of Key Symbols
| Symbol | Meaning                                                               |
|--------|-----------------------------------------------------------------------|
| U_t    | Regime entropy at time t (aleatoric uncertainty measure, in [0,1])    |
| N_MC   | Number of Monte Carlo samples (default 1,000)                         |
| W      | Walk-forward window length in bars (default 252)                      |
| CI     | Confidence interval                                                   |
| sigma  | Standard deviation (of returns or signal scores)                      |
| A      | Regime transition matrix                                              |
| seed   | Integer RNG seed; declared in config and logged per session           |
