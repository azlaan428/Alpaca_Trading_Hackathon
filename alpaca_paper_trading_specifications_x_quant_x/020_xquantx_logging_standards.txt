1.1. Abstract
This document defines the structured log schema for all X Quant X trading events: order
submissions, fills, risk-gate decisions, regime transitions, signal emissions, and operator
errors. It specifies severity levels, log rotation and retention, audit trail requirements,
and the hash-chain mechanism for tamper detection.

1.2. Key Words
structured logging, NDJSON, event_type, order, fill, risk gate, regime transition, signal,
operator error, audit trail, hash chain, log rotation, severity levels, AUDIT_LOGS.

1.3. Executive Summary
All X Quant X log entries are emitted as structured NDJSON (newline-delimited JSON) to
AUDIT_LOGS/. Every entry includes: event_type, timestamp_ns, operator_id, session_id,
payload, and audit_trail_hash (SHA-256 of the previous entry's content). Never use print()
— use the structured logger exclusively. Log level ERROR triggers a ValidationOperator
check. Risk-gate decisions must always log rule_id, verdict, triggering_value, and
threshold. Log rotation occurs daily; entries are retained for 90 days minimum.

1.4. Key Findings
1.4.1. The structured log schema has six mandatory top-level fields: event_type,
timestamp_ns, operator_id, session_id, payload, and audit_trail_hash.
1.4.2. Six canonical event types cover all platform activity: ORDER_SUBMITTED,
FILL_RECEIVED, RISK_GATE_DECISION, REGIME_TRANSITION, SIGNAL_EMITTED, OPERATOR_ERROR.
1.4.3. The audit_trail_hash is SHA-256 of the previous log entry's full JSON string
(sorted keys). This enables post-hoc tamper detection by re-computing the hash chain.
1.4.4. Log level ERROR triggers an immediate ValidationOperator.check() call; if the
ValidationOperator itself emits an error, the session is halted.
1.4.5. No print() call may appear in any operator or agent implementation; all logging
uses the xquantx.utils.logging.StructuredLogger wrapper.

1.5. Philosophical Preamble
A log is a promise that nothing important happened invisibly. In a quantitative trading
system this promise is load-bearing: a trading session's fill records, risk-gate verdicts,
and regime transitions are only as trustworthy as the structured event trail behind them.
The hash-chain mechanism ensures that no log entry can be silently modified, deleted, or
inserted after the fact — giving the platform the same auditability guarantees that
regulators and internal risk desks require.

1.6. Structured Log Schema
The canonical log entry format (NDJSON):
{
  "event_type": "ORDER_SUBMITTED",
  "timestamp_ns": 1700000000000000000,
  "operator_id": "AlpacaPaperExecutionOperator-v1.0.0",
  "session_id": "7f4a2b1c-8e3d-4f5a-b6c7-d8e9f0a1b2c3",
  "payload": {
    "order_id": "alpaca-uuid-v4",
    "symbol": "AAPL",
    "side": "buy",
    "type": "market",
    "qty": 10.0,
    "mode": "paper"
  },
  "audit_trail_hash": "sha256_of_previous_entry_hex_string"
}
All fields are mandatory. audit_trail_hash of the first entry in a session is
SHA-256("SESSION_START:{session_id}").

1.7. Event Types and Required Payload Fields
| event_type | Required payload fields |
|------------|------------------------|
| ORDER_SUBMITTED | order_id, symbol, side, type, qty, mode |
| FILL_RECEIVED | order_id, symbol, fill_price, filled_qty, remaining_qty, mode |
| RISK_GATE_DECISION | rule_id, verdict, measured_value, threshold, symbol (if applicable), mode |
| REGIME_TRANSITION | from_regime_id, to_regime_id, confidence, entropy, timestamp_ns |
| SIGNAL_EMITTED | operator_id, symbol, signal_score, confidence, regime_id |
| OPERATOR_ERROR | error_type, error_message, stack_trace_hash, inputs_hash |

1.8. Severity Levels
| Level | Meaning | Action triggered |
|-------|---------|------------------|
| DEBUG | Detailed diagnostic (not emitted in Paper mode by default) | None |
| INFO | Normal trading events (ORDER_SUBMITTED, FILL_RECEIVED, SIGNAL_EMITTED, REGIME_TRANSITION) | None |
| WARNING | Recoverable anomaly (missing bars, non-ALLOW verdict frequency spike) | Logged; operator continues |
| ERROR | Operator failure, schema validation failure | ValidationOperator.check() triggered immediately |
| CRITICAL | Session-halting condition (FLATTEN triggered, execution timeout) | Session gracefully halted |

1.9. Log Rotation and Retention
1.9.1. Log files are written to AUDIT_LOGS/{session_id}_{date}_{mode}.ndjson.
1.9.2. Daily rotation: a new log file is created at midnight UTC. The session_id is
stable across midnight boundaries.
1.9.3. Retention: log files are retained for minimum 90 days. After 90 days, log files
may be archived to compressed storage (gzip) but must not be deleted.
1.9.4. CI test logs: stored in AUDIT_LOGS/ci/ with the CI run ID as session_id prefix.

1.10. Audit Trail Hash Chain
1.10.1. Every log entry contains audit_trail_hash =
SHA-256(previous_entry_json_sorted_keys_utf8_encoded).hex().
1.10.2. The hash chain is verified by the post-session audit tool:
xquantx.utils.audit.verify_session_log(session_id).
1.10.3. Any hash chain break (hash mismatch or missing entry) is flagged as
AUDIT_INTEGRITY_FAILURE and logged to AUDIT_LOGS/integrity_failures.log.
1.10.4. Hash chain verification is a mandatory step in the backtest e2e test
(013_xquantx_end2end_testing.txt §1.6.3(h)).

1.11. No-Print Rule
1.11.1. No print() call may appear in any file under src/ (all four languages). This is
enforced by: ruff check (Python, rule T201), golangci-lint (Go, forbid fmt.Println in
production code), clang-tidy (C++, custom check), clippy (Rust,
allow(clippy::print_stdout) must not appear in library code).
1.11.2. The Python structured logger is xquantx.utils.logging.StructuredLogger. It
wraps the standard `logging` module and emits NDJSON entries to AUDIT_LOGS/.
1.11.3. Go uses a structured logger that emits JSON to stdout (captured by the session
orchestrator and written to AUDIT_LOGS/).

1.14. Risk and Mitigation Table
| Risk | Likelihood | Impact | Mitigation |
|------|-----------|--------|------------|
| audit_trail_hash not computed for a log entry | Low | High | StructuredLogger always computes hash; unit test asserts hash is present on every emitted entry |
| Log file written to wrong path (not AUDIT_LOGS/) | Low | High | StructuredLogger path is determined at session start from SessionContext; not configurable per-operator |
| print() statement slipping into production code | High | Medium | CI lint rule T201 (ruff) fails build on any print() in src/python/; same for other languages |
| Hash chain broken by out-of-order log entries in async context | Medium | High | StructuredLogger uses a thread-safe sequential queue for hash computation; no concurrent writes to same hash chain |

1.15. Conclusion
The structured NDJSON logging contract, combined with the SHA-256 audit trail hash chain
and the mandatory no-print rule, provides X Quant X with a tamper-evident, machine-readable
event record suitable for real-time diagnostics, post-session analysis, and regulatory
audit. All operators are required to emit events exclusively through
xquantx.utils.logging.StructuredLogger.
