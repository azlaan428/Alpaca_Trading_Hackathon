1.1. Abstract
This document defines the aesthetic standards for the X Quant X dashboard and visualization
layer, covering the dark-mode color palette, typography, chart grid rules, motion/transition
tokens, brand accent color usage, and accessibility standards. It is the single source of
truth for all visual design decisions in xquantx/dashboard/.

1.2. Key Words
aesthetics, dark mode, color palette, typography, chart grid, motion, brand accent, #FFACE9,
accessibility, WCAG AA, Plotly theme, Dash theme, visualization tokens.

1.3. Executive Summary
X Quant X uses a deep-navy dark-mode primary theme (#1a1a2e background) with a cool blue
primary data series color (#7ec8e3), neutral text (#e0e0e0), and a rose/pink brand accent
(#FFACE9) reserved exclusively for alert and critical states. Typography uses a monospace
font for data values (JetBrains Mono or Roboto Mono) and a sans-serif for labels (Inter or
Roboto). All charts have consistent grid lines, axis labels, and source annotations. Motion
transitions are minimal (≤ 300ms). WCAG AA contrast is enforced throughout.

1.4. Key Findings
1.4.1. Deep-navy (#1a1a2e) is the primary background for all dashboard panels and chart
backgrounds. This provides the high contrast needed for 24/7 trading monitor use without eye
fatigue.
1.4.2. The brand accent color #FFACE9 (rose/pink, as used in high_level_concept.md mermaid
diagrams) is reserved exclusively for: ALERT states (REDUCE/BLOCK/FLATTEN verdicts),
drawdown thresholds > 15% (FLATTEN trigger), and stress-regime highlighting (R04, R07). It
is never used for normal-state data series.
1.4.3. Monospace typography (JetBrains Mono 12px or Roboto Mono) is used for all numeric
values (P&L, equity, prices, percentages, signal scores). This ensures digit alignment in
tables and charts.
1.4.4. Chart grid lines use #2a2a4a (slightly lighter than background) to provide visual
structure without obscuring data series.
1.4.5. All color choices achieve WCAG AA contrast ≥ 4.5:1 on the dark background.

1.5. Aesthetic Preamble
A color system is a contract of clarity between the trading tool and the analyst monitoring
it under real market conditions; in a product whose critical output is risk-gate verdicts,
an ambiguous or inconsistent color assignment would itself constitute an operational risk.
X Quant X's aesthetic choices are not decorative — the deep-navy background is chosen for
24/7 monitor legibility, the monospace font is chosen for digit alignment, and the #FFACE9
accent is constrained to alert states precisely because visual salience degrades when a
signal color appears in non-signal contexts. Every token in this document is the output of
a legibility-first decision, not a brand preference.

1.6.2. Alert-Critical (#FFACE9) Prohibition Rules
1.6.2.1. alert-critical (#FFACE9) MUST NOT appear on any chart element that represents a
normal operating state: normal P&L, normal signal score, normal regime probability, or any
non-alert data series.
1.6.2.2. Its exclusive use for ALERT states (REDUCE/BLOCK/FLATTEN verdicts, drawdown > 15%,
R04/R07 regime segments) maintains its visual salience as a warning signal.
1.6.2.3. Any code reviewer encountering a Plotly color assignment of #FFACE9 on a non-alert
series must flag it as a specification violation.

1.6.3. Brand Accent and Border Rule
1.6.3.1. The border token (#3a3a5a) is used for all panel borders and dividers.
1.6.3.2. The text-accent token (#7ec8e3) is used as the primary series color (equity curve,
highlighted metric values) and is distinct from alert-critical (#FFACE9).
1.6.3.3. No token serves dual roles across alert and non-alert contexts.

1.6.4. Contrast and Accessibility Requirements
1.6.4.1. text-primary (#e0e0e0) on bg-primary (#1a1a2e) achieves approximately 14:1
contrast ratio (WCAG AAA; exceeds the 4.5:1 AA minimum).
1.6.4.2. text-accent (#7ec8e3) on bg-primary (#1a1a2e) achieves approximately 8.5:1
contrast ratio (WCAG AAA; exceeds the 4.5:1 AA minimum).
1.6.4.3. All numeric values and axis labels must use at least 11px rendered size. Minimum
interactive touch target for Dash components is 44px × 44px.

1.7. Typography
| Context | Font | Size | Weight |
|---------|------|------|--------|
| Numeric values (P&L, prices, %) | JetBrains Mono (fallback: Roboto Mono) | 12px–14px | Regular |
| Chart axis labels | Inter (fallback: Roboto) | 11px | Regular |
| Chart titles | Inter (fallback: Roboto) | 14px | SemiBold |
| Dashboard section headers | Inter (fallback: Roboto) | 16px | Bold |
| Table cell values | JetBrains Mono | 11px | Regular |
| Alert text (BLOCK/FLATTEN) | Inter | 12px | Bold, uppercase |

1.7.1. Monospaced font (JetBrains Mono or Roboto Mono fallback) is used for all numeric
values to ensure digit alignment in tables and charts.
1.7.2. Sans-serif font (Inter or Roboto fallback) is used for all labels, titles, headers,
and non-numeric text.
1.7.3. Alert text (BLOCK/FLATTEN verdicts displayed in the risk-gate log) uses Inter Bold
uppercase to visually differentiate from normal data text.

1.8. Chart Grid Rules
1.8.1. All charts display a horizontal grid at major Y-axis tick values; grid color: #2a2a4a.
1.8.2. No vertical grid lines. Vertical lines are used only for event markers: regime
transitions and FLATTEN triggers.
1.8.3. Event marker: a vertical dashed line in alert-critical (#FFACE9) marks every FLATTEN
verdict on the equity curve and drawdown chart.
1.8.4. Zero-reference line on signal score charts: solid horizontal line at y=0, color
#4a4a6a, width 1px.
1.8.5. Every chart has a title (top-left), axis labels (both axes), a legend, and a source
annotation ("X Quant X | {session_id} | {mode}") in the bottom-right corner in
text-secondary color (#a0a0b0).

1.9. Motion and Transition Tokens
1.9.1. Dashboard refresh rate: per-bar (1-minute default in Paper mode; configurable in
config/).
1.9.2. Chart update transition duration: ≤ 300ms using Plotly's default transition. No
animation on data-critical elements (risk-gate log, regime probabilities).
1.9.3. No infinite loading spinners. Use a static "Waiting for data..." text on panels that
have not yet received their first bar.
1.9.4. No auto-scroll on the risk-gate log table; the user pins the view manually.

1.10. Dark Mode Enforcement
1.10.1. All Plotly charts use template="plotly_dark" as the base template, overriding with
the X Quant X token colors defined in §1.6.1.
1.10.2. Dash app layout uses the DBC (Dash Bootstrap Components) darkly theme or equivalent.
1.10.3. No light-mode charts are permitted in the dashboard. All PNG exports use the dark
theme.

1.11. Accessibility
1.11.1. WCAG AA: all text on bg-primary (#1a1a2e) achieves ≥ 4.5:1 contrast. #e0e0e0 on
#1a1a2e ≈ 14:1 (passes). #7ec8e3 on #1a1a2e ≈ 8.5:1 (passes).
1.11.2. Color-blind safety: all series that convey meaning through color also use distinct
line styles (solid, dashed, dotted) or distinct marker symbols. Regime segments use both
color and text label.
1.11.3. All interactive Dash components have aria-label attributes for screen reader support.

1.16. Conclusion
X Quant X's visual aesthetic is a legibility-first, alert-aware dark-mode design: every
token is anchored to a specific functional role, and the #FFACE9 brand accent is constrained
to alert states to preserve its visual salience as a critical warning signal. These standards
are the single source of truth for xquantx/dashboard/ and supersede all prior X Quant X or
game-era aesthetic content in this file.
