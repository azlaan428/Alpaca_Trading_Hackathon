1.1. Abstract
This file is the in-repository copy of the X Quant X opening-day master prompt. It is
co-authored with and derived from CHATS/2026-08-26_alcapa-spec-rewrite-PROMPT.md §6. The
master prompt in §1.8 (The Master Prompt) is the copy-paste block submitted to an AI
code-generation platform on Day 1 of the development sprint. Section §1.9 defines the
bounded follow-up prompt discipline for subsequent prompts. Section §1.10 provides the
day-by-day pacing guide.

1.3. Executive Summary
The X Quant X opening-day master prompt consolidates all architectural decisions — operator
model, data pipeline, regime engine, risk rules, portfolio operators, execution integration,
performance attribution, testing, logging, visualization, and the specification corpus rewrite
directive — into a single, internally consistent copy-paste block. It is designed to scaffold
the platform in one submission.

1.4. Key Findings
1.4.1. The master prompt (§1.8) is a single copy-paste block; it must NOT be fragmented into
smaller prompts on Day 1.
1.4.2. All subsequent prompts must follow the bounded follow-up discipline (§1.9): TARGET /
CHANGE / PRESERVE / SCOPE / TEST format.
1.4.3. The day-by-day pacing guide (§1.10) sequences the sprint from scaffold through
validation.
1.4.4. This document is the in-repository canonical copy of the prompt;
CHATS/2026-08-26_alcapa-spec-rewrite-PROMPT.md is the planning artifact from which it derives.
1.4.5. Every META-PROMPT referenced in alcapa_trading_agents_concept/prompt_patterns.md is
represented in §1.8.

1.5. Philosophical Preamble
A master prompt is the highest-level instruction set a development sprint receives. Its
purpose is to establish consistent architectural decisions across all components before any
implementation begins. A fragmented master prompt — submitted as many small prompts over
multiple sessions — produces an inconsistent architecture where each component reflects
different implicit assumptions about the platform. Submit the master prompt whole, on Day 1,
and use bounded follow-up prompts for all subsequent changes.

1.8. The Master Prompt (Copy-Paste Block)
The following text is the literal content to submit to the AI code-generation platform on
opening day, as a single unbroken submission.

---
You are scaffolding and building the X Quant X quantitative paper-trading intelligence
platform — a multi-agent, multi-language system that continuously determines the state of
financial markets, estimates uncertainty and risk, and dynamically proposes portfolio
allocation, hedging, and trading decisions.

Repository: Alpaca_Trading_Hackathon (current workspace).
Implementation languages: Python, Go, C++, Rust.
Primary execution API: Alpaca Paper Trading API via alpaca-py SDK (tools/alpaca/alpaca-py).
Secondary execution API: Alpaca Go SDK (tools/alpaca/alpaca-trade-api-go) for
performance-critical paths.
Standards authority: coding_stds/CodingStandardsRef/coding_stds/MOST_CITED_STANDARDS.md
Tier 0-5 rules apply unconditionally.

Central research question: Given all information legitimately available at time t, what
market regime is most probable, what risks currently dominate, how uncertain is that
assessment, and what portfolio allocation, hedge, or trading action provides the best
risk-adjusted response?

Non-negotiable architectural rules:
1. Agents are software objects implementing typed interfaces (Operator, Agent, Strategy).
   Markdown does not execute agents.
2. Deterministic over magic: same input + same seed = same output for every Operator.
3. Uncertainty is a first-class citizen: every signal and decision carries an explicit
   confidence or uncertainty estimate.
4. Evidence-traceability: every order is reconstructable from raw data to features to regime
   to signal to risk verdict to allocation to order.
5. SOLID + ACID + JPL Power of Ten: all code follows these principles per
   coding_stds/CodingStandardsRef/.

Four-domain partition: Earth (Portfolio & Income), Air (Hedging & Risk), Fire (Volatility &
Options), Water (Macro & Cross-Market). Four views of one system. Options paper trading
(Fire domain, via the Alpaca Options API paper endpoint) is MANDATORY MVP scope per the
hackathon category requirement, not optional — see 001_xquantx_concept.txt §1.9.1.10.

Operator model (implement all): Operator (base), DataOperator, NormalizationOperator,
FeatureOperator, MarketRegimeOperator, SignalOperator, RiskOperator, PortfolioOperator,
HedgeOperator, ExecutionOperator, SimulationOperator, PerformanceOperator,
ValidationOperator, NewsOperator. Every Operator implements: process(), validate_inputs(),
schema_version(), operator_id().

Multi-language boundaries: Python = ML/research/orchestration/Alpaca API; Go =
streaming/services/low-latency; C++ = numerical kernels (Kalman, covariance, options
pricing); Rust = concurrent pipeline/serialization.

Canonical data schemas (define before implementing any Operator): OHLCVBar, Tick, Order,
Position, PortfolioSnapshot, RegimeState, Signal, AllocationVector — all specified in
alpaca_paper_trading_specifications_x_quant_x/021_xquantx_data_standards.txt §1.8.

Market-regime engine: Twelve canonical regimes R01-R12 (defined in
025_xquantx_scenario_catalog.txt). Methods: HMM (Baum-Welch + Viterbi), Kalman filter
state estimation, Bayesian posterior update. Regime entropy gate: U_t > 0.75 = REDUCE;
U_t > 0.90 = BLOCK new positions.

Risk rule-set (defined in 028_xquantx_risk_ruleset.txt): 10 rules. FLATTEN trigger:
drawdown > 15% from peak. BLOCK: concentration > 20%, leverage > 1.0, new long in R04/R07
with confidence <= 0.85. REDUCE: sector exposure > 35%, entropy U_t > 0.75. Kelly sizing:
f = 0.25 * f*, capped at 20% per position.

Portfolio optimization: Mean-variance (R01, R11), Risk-parity (R03, R05),
Minimum-variance (R04, R07). Finite-capital axioms per high_level_proofs/.

Operating modes: Paper (MVP, primary) and Backtest (MVP, optional).
SessionContext.mode is immutable per session.

Dashboard (7 charts): Equity curve, Drawdown waterfall, Regime probability bar,
Correlation heatmap, Signal score series, Portfolio treemap, Risk-gate log table. Dark-mode
theme (#1a1a2e), alert-critical color #FFACE9 reserved for FLATTEN/BLOCK states only.

Testing layers: Unit (100% branch on Operators), Integration (chain + sandbox API),
Simulation (4-variant regime-matrix), Performance (<=200ms order latency, >=1000 bars/sec
backtest), Shadow CI gate. See 008_xquantx_testing.txt through 014_xquantx_cicd.txt.

Parallel task: Rewrite alpaca_paper_trading_specifications_x_quant_x/ corpus per
CHATS/2026-08-26_alcapa-spec-rewrite-PLAN.md.

Explicit non-goals (MVP): Live trading (real-money execution, including live options),
advanced options strategies (Greeks-based hedging, volatility-surface strategies),
multi-broker, RL regime engine, real-time LLM news, mobile dashboard. Basic options paper
trading itself is MANDATORY MVP scope (Fire domain), not a non-goal.
---

1.9. Bounded Follow-Up Prompt Discipline
1.9.1. Every follow-up prompt after Day 1 MUST use:

TARGET: <exact file or module being modified>
CHANGE: <one-sentence description of exactly what changes>
PRESERVE: <what must NOT change>
SCOPE: <files that may be touched>
TEST: <how to verify the change>

1.9.2. NEVER submit: "make it better", "improve the signal", "fix the tests". These violate
the scope invariant.
1.9.3. Any follow-up that would alter an Operator interface, data schema, risk rule, or
dashboard specification declared in §1.8 must be routed back through this specification
corpus for an explicit, reviewed update before being sent to the AI platform — never patched
ad hoc in a follow-up prompt.
1.9.4. Fragmented Day 1 submissions (submitting §1.8 as multiple sequential prompts) are
forbidden; each sub-prompt establishes conflicting implicit defaults that are irreversible
without a full regeneration pass.
