1.1. Abstract
This document defines the complete risk rule-set for X Quant X, including maximum drawdown
limits, per-position concentration caps, sector/asset-class exposure caps, leverage limits,
regime-conditional circuit breakers, and the rule versioning and override audit trail
requirements. All rules are enforced by RiskOperator and are the sole gate for trade
execution.

1.2. Key Words
risk rule-set, drawdown limit, concentration cap, sector exposure, leverage limit, circuit
breaker, RiskVerdict, ALLOW, REDUCE, BLOCK, FLATTEN, rule-set versioning, override audit
trail, Kelly criterion, position sizing.

1.3. Executive Summary
The X Quant X risk rule-set is a versioned set of numeric thresholds that RiskOperator
evaluates against every proposed allocation before any order is submitted. Rules are declared
in config/risk_rules.toml and versioned via a RULESET_VERSION field. Every verdict other than
ALLOW is logged to AUDIT_LOGS/ with the triggering rule ID, measured value, threshold, and
timestamp. No code bypasses this rule-set. The MVP rule-set version is 1.0.0.

1.4. Key Findings
1.4.1. The rule-set is declared in config/risk_rules.toml. The file is the single source of
truth for all numeric thresholds; they must not be hardcoded in any Operator implementation.
1.4.2. RULESET_VERSION is a semver string in config/risk_rules.toml; it is logged in every
session's AUDIT_LOGS/ metadata entry so that any session's risk behavior can be exactly
reproduced.
1.4.3. All hard-limit violations produce BLOCK verdicts; soft-limit violations produce REDUCE
verdicts; the maximum-drawdown trigger produces a FLATTEN verdict; all other conditions pass
with ALLOW.
1.4.4. Rule override: no rule may be silently overridden. Any override requires a new
RULESET_VERSION, a justification logged in config/risk_rules.toml's comments, and a CI test
that validates the override produces the intended behavior.
1.4.5. Regime-conditional rules apply additional restrictions during high-risk regimes (R04,
R07) that are NOT present in other regimes; these must be evaluated as conditional branches
in RiskOperator, not as globally active rules.

1.5. Philosophical Preamble
A risk rule-set is not a bureaucratic constraint on profitable trading; it is the mathematical
formalization of "how much can we afford to be wrong?" Without explicit position limits,
drawdown gates, and sector caps, a quantitative system will discover the worst possible
concentration on the worst possible day. Every rule in this document represents a decision
made in advance, when reason is calm, to constrain decisions made under pressure, when reason
is compromised. The rules are the product, not an obstacle to it.

1.6. Hard Limits (BLOCK triggers)
1.6.1. Per-position concentration cap: no single position may represent more than 20% of
current portfolio equity after the proposed allocation. Formula: qty x current_price /
portfolio_equity <= 0.20. Violation: BLOCK (or REDUCE to 0.20 x portfolio_equity if the
excess is marginal and the signal is ALLOW-grade). Rule ID: CONC-001.

1.6.2. Gross leverage: the sum of all position market values (long + short, absolute) must
not exceed 100% of portfolio equity. Formula: sum |qty_i x price_i| / portfolio_equity <= 1.0.
Paper MVP has no margin; leverage must remain <= 1.0. Violation: BLOCK. Rule ID: LEV-001.

1.6.3. Regime-conditional new-long block: in regimes R04 (bear-capitulation) or R07
(macro-shock), no new long position may be opened unless the aggregate signal confidence is
> 0.85. Formula: regime_id in {R04, R07} AND new_long AND aggregate_confidence <= 0.85 ->
BLOCK. Rule ID: REGM-001.

1.6.4. Daily loss circuit breaker: if the session's total realized + unrealized P&L has
declined more than 5% of equity since session open, all new position-opening orders are
BLOCKED (existing positions may be closed). Rule ID: DLOSS-001.

1.7. Soft Limits (REDUCE triggers)
1.7.1. Sector exposure cap: no single GICS sector may represent more than 35% of portfolio
equity. Formula: sector_exposure / portfolio_equity <= 0.35. Violation: REDUCE the proposed
position to bring sector total back to <= 0.35. Rule ID: SECT-001.

1.7.2. Signal confidence threshold: if the aggregate signal confidence < 0.40, scale the
proposed position by (confidence / 0.40). Rule ID: CONF-001.

1.7.3. High-entropy REDUCE: if regime entropy U_t > 0.75, scale all proposed new positions
by (1 - U_t). Rule ID: ENT-001. If U_t > 0.90: BLOCK all new positions (Rule ID: ENT-002 ->
upgrades to BLOCK).

1.8. FLATTEN Triggers
1.8.1. Maximum portfolio drawdown: if the portfolio equity has declined more than 15% from
its session-high watermark, emit FLATTEN for all positions. Formula: (peak_equity -
current_equity) / peak_equity > 0.15 -> FLATTEN. Rule ID: DD-001.

1.8.2. Execution failure: if ExecutionOperator fails to confirm an order fill within 30
seconds (configurable), emit FLATTEN as a risk-abort response. Rule ID: EXEC-001.

1.9. Rule-Set Versioning
1.9.1. RULESET_VERSION is declared as a semver string in config/risk_rules.toml
(e.g. "1.0.0").
1.9.2. Every session's AUDIT_LOGS/ metadata entry includes the RULESET_VERSION at session
start.
1.9.3. A rule change (adding, removing, or modifying any threshold) increments the
appropriate semver component: PATCH for threshold adjustment, MINOR for new rule addition,
MAJOR for structural redesign.
1.9.4. The config/risk_rules.toml file is committed to version control; its git commit hash
is also logged in session metadata for exact reproducibility.

1.10. Override Audit Trail
1.10.1. No rule override may be applied at runtime without a new RULESET_VERSION and a CI
test.
1.10.2. Every REDUCE and BLOCK verdict is logged to AUDIT_LOGS/ with: session_id,
timestamp_ns, rule_id, verdict, measured_value, threshold, affected_symbol.
1.10.3. Every FLATTEN verdict is logged with all open positions at time of trigger, their
unrealized P&L, and the trigger rule_id.
1.10.4. Post-session, a risk audit report (CSV) is generated summarizing all non-ALLOW
verdicts grouped by rule_id and session date.

1.15. Conclusion
The risk rule-set provides a complete, versioned, auditable gate for all trade execution in
X Quant X. Every non-ALLOW verdict is logged with its triggering rule ID and measured value.
No code may bypass this rule-set.

1.17.2. RiskOperator reads thresholds exclusively from config/risk_rules.toml; no hardcoded
values in any Operator implementation.

written before first order submission.

integration test run.
