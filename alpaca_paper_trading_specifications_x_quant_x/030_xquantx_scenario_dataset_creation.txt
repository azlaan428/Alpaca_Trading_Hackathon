1.1. Abstract
This document defines the procedure for assembling, annotating, and versioning the in-house
historical market-scenario dataset used for backtesting, regime model calibration, and
walk-forward validation in X Quant X.

1.2. Key Words
historical dataset, OHLCV, regime annotation, train/validate/test split, data provenance,
data leakage prevention, Parquet, dataset versioning, ground-truth labeling, walk-forward
validation.

1.3. Executive Summary
The X Quant X in-house dataset consists of historical OHLCV bars and associated macro
indicators, annotated with ground-truth regime labels (R01–R12 from
025_xquantx_scenario_catalog.txt) for supervised regime model evaluation. The dataset is
assembled from the Alpaca historical data API, stored in Parquet format, versioned in a
dataset registry, and split into train/validate/test partitions with strict anti-leakage
rules.

1.4. Key Findings
1.4.1. Historical OHLCV data is pulled from the Alpaca historical data API using alpaca-py
and stored as Parquet files in data/historical/ (gitignored).
1.4.2. Ground-truth regime labels are assigned by a human-reviewed annotation procedure (not
by the model under evaluation) to enable objective regime model evaluation.
1.4.3. Train/validate/test split is time-based (walk-forward): train on earliest period,
validate on middle period, test on most recent period. No random shuffling across time
periods.
1.4.4. The temporal leakage invariant (per 019_xquantx_data_structures_algorithms.txt
§1.4.6) applies to dataset assembly: no feature computed on bar t may use data from bar t+1
or later.
1.4.5. Dataset provenance is recorded in a JSON manifest (data/historical/manifest.json)
documenting: data source, pull timestamp, symbol list, date range, data schema version, and
annotation version.

1.5. Philosophical Preamble
Data discipline is the foundation of reproducible quantitative research. A backtest that
appears profitable on corrupted, mis-labeled, or look-ahead-biased data is not a valid
backtest — it is an artifact. This document treats the dataset as a first-class engineering
artifact with the same rigor applied to source code: versioning, provenance, quality gates,
and explicit anti-leakage invariants. Where uncertainty exists (e.g. gap-fill policy edge
cases), the uncertainty is recorded explicitly rather than silently resolved with a guess.

1.6. Dataset Assembly Procedure
1.6.1. Source: Alpaca historical data API via alpaca-py client. Data pulled using
`StockHistoricalDataClient.get_stock_bars()` with timeframe=TimeFrame.Day or
TimeFrame.Minute depending on the backtest resolution.
1.6.2. Symbol universe (MVP): S&P 500 constituent ETFs (SPY, QQQ, IWM) plus up to 20
individual equity tickers selected at dataset-assembly time and documented in the manifest.
1.6.3. Date range: minimum 2 years of daily OHLCV data; minimum 6 months of 1-minute OHLCV
data for intraday backtest support.
1.6.4. Storage: each symbol is stored as a separate Parquet file:
data/historical/{symbol}_{timeframe}_{date_range}.parquet. Field names match the OHLCVBar
schema in 021_xquantx_data_standards.txt §1.8.1.
1.6.5. Macro indicator supplement: for each trading day, the following macro indicators are
stored in a companion file data/historical/macro_{date_range}.parquet: VIX daily close,
2-year yield, 10-year yield, 2s10s spread, DXY (dollar index), CRB commodity index close.
1.6.6. Missing bar handling: follow the forward-fill policy defined in
021_xquantx_data_standards.txt §1.4.6 (gaps ≤ 5 bars are forward-filled; larger gaps
produce a DataOperator warning in the manifest).

1.7. Ground-Truth Regime Labeling
1.7.1. Each daily bar is assigned a ground-truth regime label (R01–R12) by a human reviewer
using the feature signatures defined in 025_xquantx_scenario_catalog.txt §1.6.1–§1.6.12.
1.7.2. Annotation is stored in data/historical/regime_labels_{date_range}.json as a mapping:
{timestamp_ns: regime_id}.
1.7.3. Annotation review: each label is reviewed by at least one additional team member
before the dataset is marked as annotation-complete.
1.7.4. The ground-truth labels are used ONLY for evaluation of MarketRegimeOperator outputs
(precision/recall per regime class); they are NEVER used as training inputs to the
MarketRegimeOperator itself (that would constitute data leakage).

1.8. Train / Validate / Test Split
1.8.1. Split policy: time-based, non-overlapping, strictly forward in time.
1.8.2. Default split: train = first 60% of date range, validate = next 20%, test = most
recent 20%.
1.8.3. No shuffling across time periods. No random split. The test set is always the most
recent period.
1.8.4. Walk-forward validation: the validate set is used for operator hyperparameter tuning;
the test set is held out until final evaluation. No hyperparameter decisions are made by
inspecting the test set.
1.8.5. Anti-leakage rule: no feature computed on the validate or test set may have used any
data from those partitions during train-set feature operator calibration.

1.9. Dataset Versioning
1.9.1. Dataset version is a semver string stored in data/historical/manifest.json
(e.g. "1.0.0").
1.9.2. A new MINOR version is created whenever: new symbols are added, date range is
extended, or macro supplement is updated.
1.9.3. A new MAJOR version is created when: the OHLCVBar schema changes, the regime label
annotation is revised, or the forward-fill policy changes.
1.9.4. The manifest.json is committed to version control (data/historical/manifest.json is
not gitignored); only the Parquet data files are gitignored.

1.11. Quality Gates and Acceptance Criteria
1.11.1. Completeness check: all symbols in the declared symbol universe have Parquet files
covering the full declared date range; manifest.json records any DataOperator warnings for
gap-fill events.
1.11.2. Annotation-completeness check: regime_labels_{date_range}.json covers 100% of daily
bars in the declared date range with no NULL labels before a dataset version is marked
annotation-complete.
1.11.3. Provenance check: manifest.json is present, complete, and committed to version
control with the correct semver version string.
1.11.4. Anti-leakage check: a code-path trace confirms no feature operator reads beyond its
declared temporal scope (no bar t+k, k > 0, in any rolling window or lookback calculation).
1.11.5. Schema conformance check: each Parquet file passes the OHLCVBar schema validator
defined in 021_xquantx_data_standards.txt §1.8.1 before the dataset version is accepted.

1.12. Team Collaboration and Escalation Path
1.12.1. The data-pull owner is responsible for executing the Alpaca API pull, storing output
in data/historical/, and updating manifest.json before triggering annotation.
1.12.2. The annotation-review owner is responsible for cross-checking at least 10% of
ground-truth regime labels per dataset version before the dataset is marked
annotation-complete.
1.12.3. Any disagreement on regime label assignment (between initial annotator and reviewer)
must be escalated to the team lead for adjudication before the label is committed.
1.12.4. A new MAJOR dataset version triggered by a schema change (§1.9.3) requires explicit
sign-off from the team lead before any downstream module (backtester, regime model evaluator)
is migrated to the new version.

1.15. Risk and Mitigation Table
| Risk | Likelihood | Impact | Mitigation |
|------|------------|--------|------------|
| Look-ahead bias in feature computation | Medium | Critical | Anti-leakage code-path trace (§1.11.4); temporal leakage invariant from 019 §1.4.6 |
| Ground-truth labels annotated by the same model being evaluated | Low | Critical | §1.7.4 prohibition: labels are human-reviewed, never model-generated |
| Parquet data accidentally committed to version control | Low | Medium | .gitignore covering data/historical/*.parquet enforced; manifest.json explicitly exempted |
| Dataset version mismatch between modules | Medium | High | semver in manifest.json; downstream modules record their consumed dataset version in run logs |
| Missing bars not detected before training | Low | High | Gap-fill audit gate (§1.11.1) and DataOperator warning log required before annotation begins |

1.17. Conclusion
The X Quant X in-house historical market dataset is a first-class engineering artifact
governed by explicit assembly procedures (§1.6), human-reviewed regime annotation (§1.7),
time-based train/validate/test split with strict anti-leakage invariants (§1.8), and semver
dataset versioning (§1.9). The quality gates in §1.11 and the RACI in §1.16 ensure that no
dataset version reaches downstream modules without passing completeness, annotation,
provenance, and anti-leakage checks.
