1.1. Abstract
This document defines the end-to-end test suite for X Quant X, covering the complete
paper-trade cycle (data ingestion -> regime detection -> signal -> risk gate -> order
submission -> fill -> position update -> P&L attribution), historical replay e2e, and
clock-controlled deterministic replay for CI.

1.2. Key Words
end-to-end tests, paper-trade cycle, historical replay, deterministic replay,
clock-controlled, temporal leakage, regime detection, risk gate, order fill, P&L
attribution, BacktestSession, PaperSession.

1.3. Executive Summary
X Quant X e2e tests verify the complete paper-trade cycle from raw market data to
post-fill P&L attribution. Two e2e test variants exist: (1) Backtest replay e2e using
historical dataset with synthetic clock; (2) Dry-run live e2e using the Alpaca WebSocket
in Dry-run mode. Both must produce consistent results for the same seed and input data
(deterministic replay invariant). The e2e tests are the last functional test layer before
the Shadow CI gate.

1.4. Key Findings
1.4.1. Backtest replay e2e: drives BacktestSession with a 252-bar (1 trading year)
historical dataset for 5 symbols. Asserts: no temporal leakage, all regime probabilities
valid, all risk verdicts handled, P&L calculation correct (total_pl = sum(filled_qty x
(fill_price - avg_entry_price)) for closed positions).
1.4.2. Deterministic replay invariant: two runs of the same backtest e2e with the same
seed must produce byte-identical AUDIT_LOGS/ outputs (excluding wall-clock timestamps).
1.4.3. Dry-run live e2e: connects to Alpaca WebSocket in Dry-run mode for 5 trading
minutes, asserts that at least one signal emission and one risk-gate verdict occur, and
that the AUDIT_LOGS/ session file is written correctly.
1.4.4. Error recovery e2e: injects a DataOperator WARNING (simulated 6-bar gap) and
asserts that the pipeline continues (with WARNING log) rather than crashing.
1.4.5. The temporal leakage assertion is repeated at the e2e level: the AUDIT_LOGS/
output is post-processed to verify that no FeatureOperator output at bar t was produced
using data from bar t+1 or later.

1.5. Philosophical Preamble
End-to-end tests are the closest a test suite comes to standing in the trader's seat.
They exist to answer one question the lower tiers cannot: does the complete paper-trade
cycle, driven by the actual data pipeline and session infrastructure, produce a
verifiable, auditable, deterministic result that a quantitative operator can inspect and
act on with confidence
(008_xquantx_testing.txt Section 1.6.3)?

1.6. Backtest Replay E2E Test
1.6.1. Input: historical dataset (252 daily bars x 5 symbols: SPY, QQQ, AAPL, MSFT,
AMZN) from data/historical/.
1.6.2. Session: BacktestSession(config=config/backtest.toml, seed=42).
1.6.3. Assertions after full 252-bar replay:
   1.6.3.1. No uncaught exceptions during the entire session.
   1.6.3.2. Temporal leakage: for each FeatureOperator output, timestamp(output) >=
       timestamp(latest_input_bar).
   1.6.3.3. Every RegimeState has regime_probabilities.sum() in [1.0 - 1e-9, 1.0 + 1e-9].
   1.6.3.4. Every Signal has signal_score in [-1.0, 1.0] and confidence in (0, 1.0].
   1.6.3.5. Every RiskVerdict in {ALLOW, REDUCE, BLOCK, FLATTEN}.
   1.6.3.6. PortfolioSnapshot after final bar: equity > 0, cash >= 0, total_pl is a finite
       float64.
   1.6.3.7. P&L math check: total_pl = sum(fill_qty x (fill_price - avg_entry_price)) for
       all closed positions, within rounding tolerance 1e-8.
   1.6.3.8. AUDIT_LOGS/ session file exists and contains valid NDJSON entries with
       session_id, mode="backtest", RULESET_VERSION.

1.7. Deterministic Replay Invariant Test
1.7.1. Run BacktestSession(seed=42) twice on the identical historical dataset.
1.7.2. Assert: AUDIT_LOGS/ output from run 1 and run 2 are byte-identical after
stripping wall_ts fields (which contain actual wall-clock time).
1.7.3. Failure of this test indicates a non-deterministic element in the pipeline (e.g.
unseeded random, unordered dict iteration, floating-point non-determinism). The failure
message must name the first diverging AUDIT_LOGS/ line.

1.8. Dry-run Live E2E Test
1.8.1. Pre-condition: ALPACA_API_KEY and ALPACA_SECRET_KEY set to paper credentials.
1.8.2. Session: PaperSession(mode="dry_run", duration_minutes=5).
1.8.3. Assertions after 5 minutes:
   1.8.3.1. At least 3 OHLCVBars received (market is open during test).
   1.8.3.2. At least 1 Signal emitted (any operator).
   1.8.3.3. At least 1 RiskVerdict emitted.
   1.8.3.4. AUDIT_LOGS/ session file written with correct NDJSON schema.
   1.8.3.5. No uncaught exceptions.
1.8.4. This test is optional in CI (controlled by RUN_LIVE_E2E=1 environment variable).

1.9. Error Recovery E2E Test
1.9.1. Inject a simulated 6-bar gap (missing bars) in the historical dataset at bar 100.
1.9.2. Assert: DataOperator emits a WARNING log entry (gap_size=6, symbol="SPY",
start_timestamp, end_timestamp).
1.9.3. Assert: the BacktestSession continues (with halt_on_large_gap=false in this test
config) and completes all 252 bars.
1.9.4. Assert: the 6 forward-filled bars are marked with is_synthetic=true in the
AUDIT_LOGS/ data entries.

| Risk                                                                      | Likelihood | Impact | Mitigation                                                                                           |
|---------------------------------------------------------------------------|------------|--------|------------------------------------------------------------------------------------------------------|
