1.1. Abstract
This document defines the build environments and dependency management policies for all four
language layers of X Quant X: Python (virtual environment), Go (modules), C++ (CMake +
Conan), and Rust (Cargo workspace). Each language layer is independently buildable and
reproducible from its declared dependency manifest.

1.2. Key Words
virtual environment, venv, Python 3.14.4, Go modules, go.mod, CMake, Conan, Cargo,
Cargo.toml, dependency management, lock file, reproducibility, build isolation,
multi-language.

1.3. Executive Summary
Every contributor and CI job must build each language layer inside its own isolated build
environment. Python uses `python -m venv .venv-xquantx` with pinned requirements. Go uses
`go.mod` and `go.sum` for module pinning. C++ uses CMake with Conan for dependency
management. Rust uses a workspace `Cargo.toml` with `Cargo.lock`. No cross-language
dependency installation bleeds into another language's environment.

1.4. Key Findings
1.4.1. Python 3.14.4 x64 is the pinned interpreter for the Python layer; the standard tool
is `python -m venv .venv-xquantx`.
1.4.2. Go toolchain version is pinned in the `go` directive of `go.mod`; all Go dependencies
are committed in `go.sum`.
1.4.3. C++ build uses CMake >= 3.25 with Conan 2.x for Eigen and other C++ dependencies;
`conanfile.py` is the canonical dependency declaration.
1.4.4. Rust uses a workspace `Cargo.toml` at `src/rust/`; `Cargo.lock` is committed for
reproducibility.
1.4.5. Known packaging risk (Python): `lxml` has no prebuilt wheel for Python 3.14 on
Windows; use BeautifulSoup with `html.parser` for any HTML-parsing need.
1.4.6. The Python virtual environment directory (`.venv-xquantx/`) is never committed to
version control; only the requirements files are.
1.4.7. Secrets (Alpaca API key, secret key) are never stored in any environment file or
requirements file; they are loaded from environment variables (ALPACA_API_KEY,
ALPACA_SECRET_KEY) at runtime.

1.5. Philosophical Preamble
A reproducible build environment is the smallest unit of correctness a multi-language
quantitative platform can guarantee. If two contributors cannot produce byte-identical
dependency behavior in each language layer, no downstream claim about reproducible backtest
results or deterministic regime inference can be trusted. Isolating each language's build
environment is not bureaucratic overhead; it is the precondition for the Kalman filter kernel
producing the same result on two different machines.

1.6. Environment Policy
1.6.1. Python: `python -m venv .venv-xquantx` followed by activation. CI creates a fresh
venv on every run.
1.6.2. Go: `go mod download` after cloning. No global GOPATH dependencies; `go.sum` is the
lock file.
1.6.3. C++: `conan install . --build=missing` then
`cmake -B build -S . -DCMAKE_BUILD_TYPE=Release`. Dependencies defined in `conanfile.py`.
No system-level Eigen or other headers used directly.
1.6.4. Rust: `cargo build` at the workspace root (`src/rust/`). `Cargo.lock` is committed.
No system Rust toolchain requirement beyond the version pinned in `rust-toolchain.toml`.
1.6.5. Secrets management: all API keys and secrets are loaded from environment variables
only, never from files committed to version control. A `.env.example` file documents
required environment variables without values.

1.7. Dependency Management
1.7.1. Python: `requirements.txt` (pinned runtime) and `requirements-dev.txt` (pinned
dev/test/lint). Key runtime dependencies: `alpaca-py`, `numpy`, `scipy`, `pandas`,
`plotly`, `dash`, `hmmlearn`, `scikit-learn`, `pyarrow`. Key dev dependencies: `pytest`,
`pytest-cov`, `mypy`, `ruff`.
1.7.2. Go: `go.mod` declares minimum Go version and direct dependencies; `go.sum` pins all
transitive dependencies. Key dependency: `github.com/alpacahq/alpaca-trade-api-go`.
1.7.3. C++: `conanfile.py` declares all C++ dependencies with pinned versions. Key
dependency: `Eigen3`. `CMakeLists.txt` links to Conan-provided targets.
1.7.4. Rust: `Cargo.toml` (workspace root) declares workspace members and shared
dependencies with pinned versions. Key dependencies: `arrow2`, `parquet2`, `tokio`,
`serde`, `serde_json`. `Cargo.lock` pins all transitive dependencies.
1.7.5. No dependency is installed without being added to the appropriate manifest in the
same change.

1.8. Reproducibility Requirements
1.8.1. A fresh clone, given only the four dependency manifests and the pinned toolchain
versions, must produce an identical build on any supported platform.
1.8.2. Dependency upgrades are deliberate, reviewed changes, not side effects of unrelated
feature branches.
1.8.3. CI validation: each language layer is built from scratch (no cache reuse for
dependency installation) in the CI pipeline on every merge.

1.11. Risk and Mitigation Table
| Risk                                                           | Likelihood | Impact   | Mitigation                                                                                |
|----------------------------------------------------------------|------------|----------|-------------------------------------------------------------------------------------------|
| Python `lxml` fails on Windows/Python 3.14                    | High       | Medium   | §1.4.5 rule: use BeautifulSoup + html.parser instead                                      |
| Go dependency version drift (no go.sum committed)             | Low        | High     | go.sum is always committed; CI runs `go mod verify`                                       |
| C++ Conan center package unavailable                          | Low        | High     | Conan center + fallback local cache; pin exact version in conanfile.py                    |
| API keys accidentally committed in requirements or .env       | Medium     | Critical | §1.6.5 secrets policy; CI pre-commit hook scans for key patterns                          |
| Rust nightly toolchain breaking stable builds                 | Low        | Medium   | rust-toolchain.toml pins stable channel + specific version                                |

1.13. Conclusion
The four-language build environment policy ensures that every contributor and CI job produces
identical builds from the same dependency manifests. Per-language isolation prevents
cross-contamination and enables independent upgrades of each language layer.
