1.1. Abstract
This document defines the integration test suite for X Quant X, covering Operator chain
integration, multi-asset pipeline integration, the regime-detection-to-signal-to-risk-gate
pipeline within a single process, and Alpaca paper-trading API integration tests using the
Alpaca sandbox environment.

1.2. Key Words
integration tests, operator chain, multi-asset pipeline, regime-to-signal, risk gate,
Alpaca sandbox, paper trading API, pytest integration, go test integration, contract tests,
DAG integration.

1.3. Executive Summary
X Quant X integration tests verify that Operators compose correctly in chains:
DataOperator -> FeatureOperator -> MarketRegimeOperator -> SignalOperator -> RiskOperator
-> PortfolioOperator -> ExecutionOperator. A separate Alpaca sandbox integration test suite
verifies that AlpacaPaperExecutionOperator correctly connects to the Alpaca paper API,
submits orders, and receives fills. Integration tests do not use mocks for the
inter-operator data flow -- they use real OHLCVBar fixtures and assert on the actual outputs
of the complete chain.

1.4. Key Findings
1.4.1. Operator chain tests verify that each typed interface boundary (OperatorOutputs from
one Operator matching OperatorInputs of the next) is satisfied in practice, not just in
schema. A schema mismatch that passes unit tests may still fail at the integration boundary.
1.4.2. The regime-to-signal-to-risk-gate pipeline test is the core integration test: it runs
a 60-bar sequence through the full pipeline and asserts that: the regime state probability
vector sums to 1.0, each signal score is in [-1, 1], and the risk-gate verdict is one of
{ALLOW, REDUCE, BLOCK, FLATTEN}.
1.4.3. Alpaca sandbox integration tests connect to https://paper-api.alpaca.markets and
verify: account info retrieval, order submission (market order for AAPL), fill confirmation,
and position update.
1.4.4. Multi-asset pipeline test: runs 5 symbols simultaneously through the pipeline and
asserts that AllocationVector weights sum to <= 1.0 and no single weight exceeds 0.20 (per
CONC-001 risk rule).
1.4.5. Cross-language integration: the Go streaming service integration test connects a mock
Alpaca WebSocket server, receives OHLCVBar JSON events, and verifies they are delivered
correctly to the Python pipeline via IPC.

1.5. Philosophical Preamble
Unit tests verify that each Operator computes its output correctly in isolation. Integration
tests verify that Operators speak the same language when connected. A schema-validated output
from SignalOperator is only trustworthy at the RiskOperator input if the two sides of the
typed interface boundary have been tested together, not just separately. Integration tests are
the proof that the composition algebra works in practice.

1.6. Operator Chain Integration Tests

1.6.1. Full pipeline chain test: DataOperator -> NormalizationOperator -> FeatureOperator
-> MarketRegimeOperator -> MomentumSignalOperator -> RiskOperator ->
MeanVariancePortfolioOperator. Input: 60 synthetic daily OHLCVBars for a single symbol.
Assertions:
   (a) RegimeState.regime_probabilities.values() sums to 1.0 +/- 1e-9
   (b) SignalScore.signal_score in [-1, 1]
   (c) RiskOperator.verdict in {ALLOW, REDUCE, BLOCK, FLATTEN}
   (d) AllocationVector.weights sum to <= 1.0
   (e) No NaN or Inf in any intermediate output

1.6.2. Chain test with stress-regime input: same test using 60 bars calibrated to produce
R04 (bear-capitulation) regime. Assertion: RiskOperator must emit BLOCK (per REGM-001 rule)
for any new long signal when confidence < 0.85 and regime = R04.

1.6.3. SignalAggregationOperator integration test: three SignalOperators (Momentum,
MeanReversion, MacroTrend) connected to SignalAggregationOperator. Assertion: aggregate
signal score in [-1, 1]; confidence in (0, 1]; aggregate confidence <= max(individual
confidences).

1.7. Multi-Asset Pipeline Integration Test

1.7.1. Run the full operator chain for 5 symbols simultaneously (SPY, QQQ, AAPL, MSFT,
AMZN).

1.7.2. Assert: PortfolioOperator produces an AllocationVector where all weights sum to
<= 1.0 and no individual weight exceeds 0.20 (CONC-001 enforcement).

1.7.3. Assert: regime state is shared across all symbols (one MarketRegimeOperator per
session, not per symbol).

1.7.4. Assert: RiskOperator evaluates portfolio-level constraints (sector cap SECT-001)
correctly across all 5 positions simultaneously.

1.8. Alpaca Sandbox Integration Tests

1.8.1. Pre-condition: ALPACA_API_KEY and ALPACA_SECRET_KEY environment variables must be
set to paper trading credentials.

1.8.2. Test: AlpacaPaperExecutionOperator.submit_order(symbol="AAPL", side="buy", qty=1,
type="market") -> verify order_id is returned and order status is "new" or "filled".

1.8.3. Test: retrieve account info -> verify equity > 0, buying_power > 0.

1.8.4. Test: cancel order -> verify order status transitions to "cancelled".

1.8.5. Sandbox test isolation: each sandbox test starts by cancelling all open orders and
closing all positions to ensure a clean state.

1.8.6. Sandbox tests are optional in CI (controlled by RUN_SANDBOX_TESTS=1 environment
variable) to avoid rate limiting and network dependencies in the core CI loop.

1.9. Cross-Language Integration Test

1.9.1. Go -> Python IPC integration test: start the Go streaming service
(src/go/cmd/streamer/) against a mock Alpaca WebSocket server (httptest), verify that
OHLCVBar events arrive at the Python pipeline's DataOperator input within 500ms.

1.9.2. C++ kernel integration test: Python calls the Kalman filter C++ kernel via ctypes or
pybind11 wrapper, verifies the result matches the Python reference implementation (pure
Python Kalman step) to within 1e-10.

1.14. Conclusion
Seven integration test scopes give X Quant X confidence that its correctly unit-tested
Operators also cooperate correctly across typed interface boundaries, that the Alpaca sandbox
API behaves as specified, and that the Go streaming and C++ kernel layers integrate cleanly
with the Python pipeline, ahead of full end-to-end validation in
013_xquantx_end2end_testing.txt.
